# payments/provider-settings Specification

## Purpose
Универсальная модель настроек внешних провайдеров на проект (платёжные системы, токены соцсетей и другие внешние сервисы): группировка, секретные credentials, произвольные properties, URL-ы возврата и статус жизненного цикла, плюс admin API управления этими настройками.

## Requirements

### Requirement: Модель настроек провайдера на проект
Система SHALL хранить настройки внешнего провайдера для каждого проекта с атрибутами: `group` (категория провайдера, например `payments`), `label` (подпись категории/провайдера), `name` (отображаемое имя, например `Platega`), `provider` (машинный ключ), `credentials` (JSON-объект секретов), `properties` (JSON-объект дополнительной информации: статусы ошибок провайдера, диагностика, произвольные параметры), `return_url`, `fail_url`, `status` (`active` | `archived`), `project_id`. На один проект и один провайдер SHALL существовать не более одной записи настроек.

#### Scenario: Уникальность настроек на пару проект+провайдер
- **WHEN** для проекта повторно сохраняются настройки провайдера `platega`
- **THEN** существующая запись обновляется, дубликат не создаётся

#### Scenario: Credentials хранятся зашифрованно
- **WHEN** настройки провайдера с credentials сохранены
- **THEN** значения credentials хранятся в БД в зашифрованном виде и недоступны в открытом тексте на уровне хранилища

### Requirement: Список настроек провайдеров проекта
Система SHALL предоставлять admin-эндпоинт списка настроек провайдеров проекта, доступный при праве `pay.providers.view`. Список SHALL включать для каждого провайдера: group, label, name, provider, status, `return_url`, `fail_url`, признак наличия credentials — но НЕ значения credentials.

#### Scenario: Просмотр списка без раскрытия секретов
- **WHEN** оператор с правом `pay.providers.view` запрашивает список провайдеров проекта
- **THEN** ответ содержит статусы и метаданные провайдеров, значения credentials в ответе отсутствуют

#### Scenario: Нет права — нет доступа
- **WHEN** оператор без права `pay.providers.view` запрашивает список провайдеров проекта
- **THEN** система возвращает ошибку доступа в стандартном envelope

### Requirement: Просмотр настроек провайдера для редактирования
Система SHALL предоставлять admin-эндпоинт просмотра настроек конкретного провайдера, доступный при праве `pay.providers.manage`, возвращающий полные настройки, включая расшифрованные credentials и properties — для заполнения формы редактирования и копирования между проектами.

#### Scenario: Полные настройки под правом manage
- **WHEN** оператор с правом `pay.providers.manage` запрашивает настройки провайдера `platega`
- **THEN** ответ содержит credentials, properties, `return_url`, `fail_url` и status

#### Scenario: Провайдер ещё не настроен
- **WHEN** запрошены настройки провайдера, для которого запись в проекте отсутствует
- **THEN** система возвращает пустую заготовку настроек (без credentials, статус по умолчанию), а не ошибку

### Requirement: Сохранение настроек провайдера
Система SHALL предоставлять admin-эндпоинт upsert-сохранения настроек провайдера при праве `pay.providers.manage`. Валидация SHALL требовать: `credentials` и `properties` — JSON-объекты (ключ → скалярное значение или вложенная структура), `return_url`/`fail_url` — корректные URL либо пусто, `status` — одно из `active`/`archived`, `provider` — известный системе ключ провайдера.

#### Scenario: Успешное сохранение настроек Platega
- **WHEN** оператор с правом `pay.providers.manage` сохраняет настройки `platega` с валидными credentials, URL-ами и статусом `active`
- **THEN** настройки сохранены и последующее чтение возвращает те же значения

#### Scenario: Невалидные данные отклоняются
- **WHEN** оператор сохраняет настройки с некорректным URL или неизвестным статусом
- **THEN** система возвращает ошибку валидации в стандартном envelope и ничего не сохраняет

### Requirement: Жизненный цикл настроек
Настройки провайдера со статусом `archived` SHALL сохранять данные, но провайдер SHALL считаться неактивным: платежи через него инициировать нельзя.

#### Scenario: Архивный провайдер не принимает платежи
- **WHEN** настройки `platega` в проекте имеют статус `archived` и инициируется платёж через `platega`
- **THEN** система возвращает доменную ошибку «провайдер не настроен/неактивен», платёж не создаётся
