# content-seo-catalog Specification

## Purpose
Каталог SEO проекта в content-сервисе: чтение SEO-полей всех сущностей контента одним списком и фоновый пересбор этих полей по AI.

## Requirements

### Requirement: Каталог SEO проекта

Content-сервис SHALL предоставлять admin-эндпоинт списка SEO-записей проекта: по одной записи на сущность контента (пост, страница, категория) с типом сущности, её идентификатором, названием, датой изменения и всеми SEO-полями — title, description, keywords, canonical, robots, og:title, og:description, og:image, twitter card, JSON-LD. Список SHALL поддерживать отбор по типу сущности, сортировку по типу, названию и дате изменения и постраничную навигацию. Эндпоинт SHALL требовать право `content.seo.manage` и SHALL быть закрыт гейтом сервиса `content`. Ответ MUST содержать только сущности текущего проекта.

#### Scenario: Список SEO проекта

- **WHEN** оператор с правом `content.seo.manage` запрашивает каталог SEO
- **THEN** ответ содержит записи постов, страниц и категорий проекта со всеми SEO-полями

#### Scenario: Сущность без SEO

- **WHEN** у сущности контента нет сохранённого SEO
- **THEN** она присутствует в каталоге с пустыми SEO-полями и признаком незаполненности

#### Scenario: Изоляция по проекту

- **WHEN** каталог запрашивается для проекта A
- **THEN** в ответе отсутствуют сущности других проектов

#### Scenario: Сервис контента выключен

- **WHEN** сервис `content` выключен для проекта
- **THEN** эндпоинт каталога отвечает 404

### Requirement: Фоновый пересбор SEO по AI

Content-сервис SHALL предоставлять admin-эндпоинт запуска пересбора SEO-полей по AI: для перечисленных сущностей или для всех сущностей проекта. Запуск SHALL требовать право `content.seo.manage`, выполняться фоновой задачей и немедленно возвращать принятую задачу. Задача SHALL иметь собственный вид фоновой работы и отдаваться списком фоновых задач проекта с состоянием, ходом и причиной отказа. Пока задача пересбора проекта выполняется, повторный запуск SHALL отклоняться доменной ошибкой.

#### Scenario: Запуск пересбора

- **WHEN** оператор запускает пересбор SEO для всех сущностей проекта
- **THEN** ответ содержит принятую задачу, а список фоновых задач показывает её как выполняющуюся

#### Scenario: Повторный запуск отклоняется

- **WHEN** пересбор SEO проекта уже выполняется и приходит второй запуск
- **THEN** ответ — 422 с сообщением о выполняющейся задаче, вторая задача не создаётся

#### Scenario: Пересбор перечисленных сущностей

- **WHEN** запуск содержит список сущностей
- **THEN** пересобираются SEO-поля только этих сущностей

### Requirement: Отказ AI не разрушает сохранённое SEO

Пересбор SHALL записывать только успешно полученные от AI поля. Отказ AI по сущности MUST NOT затирать её сохранённые SEO-поля и MUST NOT останавливать обработку остальных сущностей задачи. Итог задачи SHALL содержать число обработанных сущностей и причину отказа в понятном виде, если отказы были.

#### Scenario: AI отказал по одной сущности

- **WHEN** AI отказывает при пересборе одной из сущностей задачи
- **THEN** её прежние SEO-поля сохраняются, остальные сущности обрабатываются, а итог задачи содержит причину отказа

#### Scenario: AI недоступен

- **WHEN** AI недоступен на протяжении всей задачи
- **THEN** задача завершается отказом с причиной, SEO-поля сущностей остаются прежними
