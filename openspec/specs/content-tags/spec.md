# content-tags Specification

## Purpose
Определяет теги постов: свободные метки в дополнение к дереву категорий, которые оператор ставит вручную и которые проставляет генерация поста, оставаясь в пределах своего проекта.

## Requirements

### Requirement: Теги поста

Пост SHALL иметь набор тегов. Оператор SHALL иметь возможность добавлять и убирать теги при создании и правке поста. Указание тега, которого ещё нет в проекте, MUST создавать его. Повторное указание того же тега MUST NOT создавать дубликат.

#### Scenario: Оператор добавляет тег

- **WHEN** оператор сохраняет пост с новым тегом
- **THEN** тег создаётся в проекте и привязывается к посту

#### Scenario: Существующий тег переиспользуется

- **WHEN** оператор ставит посту тег, уже существующий в проекте
- **THEN** используется существующий тег, дубликат не создаётся

#### Scenario: Тег снят

- **WHEN** оператор убирает тег у поста и сохраняет его
- **THEN** пост больше не связан с этим тегом, сам тег в проекте остаётся

### Requirement: Теги принадлежат проекту

Теги SHALL быть изолированы по проекту: список тегов и подсказки при вводе MUST содержать только теги текущего проекта. Тег одного проекта MUST NOT привязываться к посту другого проекта.

#### Scenario: Список тегов ограничен проектом

- **WHEN** оператор смотрит теги проекта
- **THEN** он видит только теги этого проекта

#### Scenario: Одинаковые теги в разных проектах

- **WHEN** в двух проектах заведён тег с одним и тем же названием
- **THEN** это разные теги, и снятие тега в одном проекте не влияет на другой

### Requirement: Теги в ответах API постов

Ответы API по посту SHALL содержать его теги. Публичное API SHALL позволять отбирать опубликованные посты по тегу.

#### Scenario: Тег виден в ответе

- **WHEN** запрашивается пост с тегами
- **THEN** ответ содержит список его тегов

#### Scenario: Отбор публичных постов по тегу

- **WHEN** публичное API запрашивает посты по тегу
- **THEN** возвращаются только опубликованные посты проекта с этим тегом
