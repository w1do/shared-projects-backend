# instruct-schema-presets Specification

## Purpose
Определяет готовые наборы полей ответа модели по сущностям платформы: оператор берёт пресет вместо того, чтобы писать JSON Schema с нуля, а платформа гарантирует, что описанные в схеме поля — ровно те, которые она разбирает при генерации.

## Requirements

### Requirement: Каталог пресетов схем по сущностям платформы

Платформа SHALL предоставлять каталог пресетов схем ответа. Каждый пресет SHALL относиться к сущности платформы, которую заполняет генерация (категории проекта, пост, SEO-поля), и SHALL содержать перечень полей с именем, типом, признаком обязательности и кратким назначением. Состав полей пресета MUST соответствовать тому, что платформа реально разбирает из ответа модели для этой сущности; поле, которое платформа не разбирает, MUST NOT попадать в пресет. Каталог SHALL быть доступен консоли одним запросом и MUST NOT зависеть от проекта.

#### Scenario: Оператор получает состав полей сущности

- **WHEN** консоль запрашивает каталог пресетов
- **THEN** возвращаются пресеты по сущностям платформы с полями, типами, обязательностью и назначением каждого поля

#### Scenario: Пресет SEO покрывает все поля

- **WHEN** оператор берёт пресет SEO-полей
- **THEN** в схему попадают все SEO-поля, которые платформа сохраняет для материала, а не только заголовок и описание

#### Scenario: Пресеты одинаковы для всех проектов

- **WHEN** каталог запрашивается из разных проектов
- **THEN** состав пресетов одинаков и не зависит от данных проекта

### Requirement: Пресет соответствует категории инструкции

Каждый пресет SHALL быть связан с категориями инструкций, для которых он применим. Консоль SHALL предлагать оператору в первую очередь пресеты, применимые к выбранной категории инструкции. Пресет, не применимый к категории, MUST оставаться доступным, но MUST NOT предлагаться по умолчанию.

#### Scenario: Предложение по категории

- **WHEN** оператор создаёт инструкцию категории «SEO поста»
- **THEN** по умолчанию предлагается пресет SEO-полей

#### Scenario: Другой пресет остаётся доступен

- **WHEN** оператор в той же инструкции выбирает пресет другой сущности
- **THEN** пресет применяется, платформа не блокирует выбор

### Requirement: Применённый пресет остаётся правимым

Применение пресета SHALL заполнять схему инструкции его полями, не заменяя название, категорию и текст правила. После применения оператор SHALL иметь возможность убрать лишние поля, добавить свои и изменить обязательность. Итоговая схема MUST сохраняться как обычная схема инструкции и MUST оставаться корректной JSON Schema.

#### Scenario: Пресет как отправная точка

- **WHEN** оператор применяет пресет и убирает часть полей
- **THEN** сохраняется схема с оставшимися полями, остальные поля инструкции не меняются

#### Scenario: Своё поле поверх пресета

- **WHEN** оператор добавляет к пресету собственное поле
- **THEN** сохранённая схема содержит и поля пресета, и добавленное поле
