# content-topics Specification

## Purpose
Определяет промежуточное звено между исследованием и постом: собранный материал превращается в список конкретных тем для публикаций, из которого оператор выбирает, о чём писать.

## Requirements

### Requirement: Извлечение тем из исследования

Оператор SHALL иметь возможность получить список тем постов по завершённому исследованию. Темы SHALL выводиться из собранного материала, а не из одного лишь исходного запроса. Число тем MAY задаваться при запуске; незаданное MUST браться из применяемой инструкции.

#### Scenario: Запрос превращается в темы

- **WHEN** оператор извлекает темы по завершённому исследованию с запросом «Расскажи про топ-10 автомобилей»
- **THEN** он получает список отдельных тем постов, каждая пригодна как тема отдельной публикации

#### Scenario: Исследование не завершено

- **WHEN** оператор запрашивает темы по выполняющемуся или неуспешному исследованию
- **THEN** запрос отклоняется с понятным сообщением, темы не создаются

### Requirement: Состав темы

Каждая тема SHALL содержать заголовок и краткое пояснение, чем она интересна, ссылку на исследование, из которого получена, и предложенную категорию. Предложенная категория SHALL выбираться из категорий проекта, если подходящая существует; иначе тема SHALL хранить предложенное название новой категории.

#### Scenario: Тема связана с материалом

- **WHEN** оператор открывает тему
- **THEN** он видит её заголовок, пояснение, исследование-источник и предложенную категорию

#### Scenario: Подходящей категории нет

- **WHEN** ни одна категория проекта не подходит теме
- **THEN** тема хранит предложенное название категории, а существующие категории не изменяются

### Requirement: Жизненный цикл темы

Тема SHALL иметь состояние: предложена, использована, отклонена. Написание поста по теме MUST переводить её в состояние «использована» со ссылкой на созданный пост. Оператор SHALL иметь возможность отклонить тему; отклонённая тема MUST NOT предлагаться в списке для написания поста.

#### Scenario: Тема использована

- **WHEN** по теме написан пост
- **THEN** тема отмечена как использованная и ссылается на созданный пост

#### Scenario: Тема отклонена

- **WHEN** оператор отклоняет тему
- **THEN** она перестаёт предлагаться при создании поста, но остаётся в истории

#### Scenario: Повторное использование темы

- **WHEN** оператор запускает написание поста по уже использованной теме
- **THEN** запуск отклоняется с понятным сообщением, ранее созданный пост не изменяется

### Requirement: Темы принадлежат проекту

Каждая тема SHALL принадлежать проекту исследования, из которого получена. Список тем SHALL возвращать только темы текущего проекта; обращение к теме другого проекта MUST NOT раскрывать её существование.

#### Scenario: Список ограничен проектом

- **WHEN** оператор смотрит список тем
- **THEN** он видит только темы текущего проекта

### Requirement: Повторное извлечение тем не плодит дубликаты

Повторное извлечение тем по тому же исследованию MUST NOT создавать дубликаты уже существующих тем и MUST NOT сбрасывать состояние использованных и отклонённых тем.

#### Scenario: Повторное извлечение

- **WHEN** оператор повторно извлекает темы по исследованию, часть тем которого уже использована
- **THEN** использованные и отклонённые темы сохраняют своё состояние, а в список добавляются только новые темы
