# console-project-switch Specification

## Purpose
Определяет работу оператора с текущим проектом из верхней панели консоли: какой проект открыт сейчас, что в нём происходило и как перейти в другой проект, не выходя из консоли.

## Requirements

### Requirement: Текущий проект и его активность в верхней панели

Верхняя панель SHALL показывать название текущего проекта и число событий его журнала действий. Число MUST относиться к текущему проекту и обновляться при переключении на другой проект. Пока число не получено, панель SHALL показывать название проекта без него, а не пустое место. Недоступность журнала MUST NOT ломать панель: показывается название без числа.

#### Scenario: Оператор видит текущий проект

- **WHEN** оператор открывает консоль
- **THEN** в верхней панели показано название текущего проекта и число событий его журнала

#### Scenario: Журнал недоступен

- **WHEN** платформа не отдаёт журнал действий проекта
- **THEN** в панели остаётся название проекта без числа, раздел продолжает работать

#### Scenario: Нет права на журнал

- **WHEN** у оператора нет права смотреть журнал действий
- **THEN** показано название проекта без числа, отказ оператору не показывается

### Requirement: Окно проекта открывается из панели

Клик по кнопке текущего проекта SHALL открывать модальное окно проекта. Окно SHALL содержать список проектов оператора, отметку текущего и последние события текущего проекта. Закрытие окна MUST NOT менять текущий проект.

#### Scenario: Окно открывается

- **WHEN** оператор нажимает кнопку текущего проекта
- **THEN** открывается окно со списком его проектов и текущим, отмеченным как выбранный

#### Scenario: Закрытие без выбора

- **WHEN** оператор закрывает окно, ничего не выбрав
- **THEN** текущий проект и разделы консоли не меняются

### Requirement: Последние события проекта видны в окне

Окно проекта SHALL показывать последние 10 событий журнала действий текущего проекта: что произошло, над чем и когда. События SHALL идти от свежих к старым. Пустой журнал SHALL показываться понятным сообщением, а не пустым местом.

#### Scenario: События показаны

- **WHEN** оператор открывает окно проекта, в журнале которого есть записи
- **THEN** показаны последние 10 событий от свежих к старым с действием, предметом и временем

#### Scenario: Журнал пуст

- **WHEN** в журнале проекта нет записей
- **THEN** окно сообщает, что событий пока нет

### Requirement: Переключение на другой проект

Оператор SHALL иметь возможность выбрать в окне другой свой проект. После выбора консоль SHALL сделать его текущим и обновить разделы под него без перезагрузки страницы вручную. Данные прежнего проекта MUST NOT оставаться в разделах после переключения. Отказ платформы SHALL показываться понятным сообщением, а текущий проект MUST оставаться прежним.

#### Scenario: Переход в другой проект

- **WHEN** оператор выбирает в окне другой проект
- **THEN** консоль показывает данные выбранного проекта, а кнопка панели — его название и число событий

#### Scenario: Возврат к прежнему проекту

- **WHEN** оператор снова выбирает прежний проект
- **THEN** разделы снова показывают его данные

#### Scenario: Платформа отклонила переключение

- **WHEN** платформа отвечает ошибкой при переходе в выбранный проект
- **THEN** оператор видит понятное сообщение, текущий проект остаётся прежним

### Requirement: Список проектов ограничен проектами оператора

Окно SHALL показывать только проекты, доступные текущему оператору. Проект, участником которого оператор не является, MUST NOT предлагаться к выбору. Оператор с единственным проектом SHALL видеть окно с этим проектом и его событиями, без предложения переключиться.

#### Scenario: Чужие проекты не предлагаются

- **WHEN** оператор открывает окно проекта
- **THEN** в списке только проекты, в которых он состоит

#### Scenario: Единственный проект

- **WHEN** у оператора один проект
- **THEN** окно показывает его как текущий и его события, список выбора не предлагает других проектов
