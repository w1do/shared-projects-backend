# console-localization-ui Specification
## Purpose

Даёт оператору управлять языками проекта из панели: состав локалей, словарь переводов с автопереводом и переводимые поля контента — без обращения к API вручную.

## Requirements

### Requirement: Управление локалями проекта

Вкладка Languages SHALL показывать локали проекта и позволять оператору с правом настроек добавлять и удалять их; первая локаль SHALL быть помечена как локаль по умолчанию. Изменения MUST сохраняться в платформе и действовать после обновления данных проекта.

#### Scenario: Добавление локали

- **WHEN** оператор добавляет локаль `en` к проекту с локалью `ru`
- **THEN** проект сохраняется с локалями `ru, en`, и `en` доступна для переводов

### Requirement: Словарь переводов в панели

Вкладка SHALL показывать записи словаря с ключом и значениями по локалям проекта; значения редактируются и сохраняются, ключи создаются и удаляются; есть поиск по ключу. Значение, созданное автопереводом, SHALL быть помечено; ручное сохранение снимает пометку.

#### Scenario: Правка значения

- **WHEN** оператор меняет русское значение ключа и сохраняет
- **THEN** значение сохранено, прочие локали не тронуты, пометка автоперевода снята

#### Scenario: Пометка автоперевода видна

- **WHEN** значение локали создано автопереводом
- **THEN** в таблице у него виден признак машинного перевода

### Requirement: Запуск автоперевода из панели

Кнопка «Translate missing» SHALL ставить фоновый автоперевод недостающих локалей; оператор SHALL получать подтверждение постановки. Отказ (нет права, ошибка) SHALL показываться понятным сообщением.

#### Scenario: Постановка автоперевода

- **WHEN** оператор нажимает «Translate missing»
- **THEN** задача поставлена, показано подтверждение, панель остаётся работоспособной

### Requirement: Имя категории вводится по локалям

Форма категории (режим api) SHALL показывать поле имени для каждой локали проекта; заполненные значения сохраняются набором, slug остаётся единым. Пустые не-дефолтные локали допустимы (откат на локаль по умолчанию).

#### Scenario: Сохранение имени по локалям

- **WHEN** оператор вводит имя на `ru` и `en` и сохраняет категорию
- **THEN** обе локали читаются обратно, slug один

### Requirement: Тексты консоли из словаря переводов

Тексты интерфейса консоли SHALL определяться реестром ключей `console.*` с русскими значениями по умолчанию. Панель SHALL запрашивать плоский словарь переводов текущего проекта по локали оператора и применять найденные значения ключей `console.*` поверх значений по умолчанию; отсутствие ключа в словаре SHALL приводить к показу значения по умолчанию, а не пустой строки. Кэш словаря SHALL инвалидироваться по версии переводов из bootstrap.

#### Scenario: Текст без переопределения

- **WHEN** ключ `console.*` отсутствует в словаре проекта
- **THEN** интерфейс показывает русское значение по умолчанию

#### Scenario: Переопределение через словарь

- **WHEN** оператор добавляет в словарь проекта ключ `console.*` со значением для своей локали
- **THEN** после обновления данных панель показывает значение из словаря вместо значения по умолчанию

#### Scenario: Недоступность словаря не ломает панель

- **WHEN** словарь переводов недоступен (сервис content выключен или запрос упал)
- **THEN** панель работает с русскими значениями по умолчанию без ошибок интерфейса
