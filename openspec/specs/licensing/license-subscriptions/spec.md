# licensing/license-subscriptions Specification

## Purpose

Окно обновлений лицензии, управляемое подпиской: организация подписывается на лицензионный план с ценой, perpetual-лицензия выпускается автоматически, а оплата каждого периода сдвигает `updates_until` и поднимает право на версии — сама лицензия бессрочна, ручной выпуск полностью сохраняется.

## Requirements

### Requirement: Авто-выпуск лицензии при оформлении подписки

При оформлении подписки, где подписчик — организация, а предмет — лицензионный план текущего проекта, система SHALL автоматически выпустить perpetual-лицензию этой организации по этому плану: `updates_until` = конец оплаченного периода подписки, `entitled_version` — версия последнего релиза проекта на момент выпуска (пусто при отсутствии релизов), `max_installations = 1`, entitlements (edition, снимок фич) — как при ручном выпуске. Поскольку ответ оформления подписки ключ не возвращает, активационный ключ авто-выпущенной лицензии SHALL храниться в зашифрованном виде до первого показа: оператор с правом `pay.licensing.manage` SHALL иметь возможность один раз запросить показ ключа, после чего зашифрованная копия SHALL необратимо удаляться (в хранилище остаётся только хэш). Если у организации уже есть неотозванная лицензия по этому плану, система SHALL продлить её окно обновлений вместо выпуска второй.

#### Scenario: Лицензия выпускается вместе с подпиской

- **WHEN** оператор оформляет подписку организации на лицензионный план с ценой
- **THEN** у организации появляется лицензия по этому плану со статусом `active` и `updates_until`, равным концу оплаченного периода подписки

#### Scenario: Ключ авто-выпущенной лицензии показывается один раз

- **WHEN** оператор с правом `pay.licensing.manage` запрашивает показ ключа авто-выпущенной лицензии, а затем запрашивает его повторно
- **THEN** первый запрос возвращает полный ключ, повторный — доменную ошибку валидации: зашифрованная копия удалена, в хранилище остался только хэш

#### Scenario: Существующая лицензия продлевается, а не дублируется

- **WHEN** подписка оформляется для организации, у которой уже есть неотозванная лицензия по этому плану
- **THEN** вторая лицензия не создаётся; `updates_until` существующей сдвигается на конец оплаченного периода, `entitled_version` поднимается по каталогу релизов, ключ прежний

### Requirement: Продление лицензии оплатой периода подписки

При успешной оплате периода подписки организации на лицензионный план система SHALL продлить связанную неотозванную лицензию: `updates_until` устанавливается в новый конец оплаченного периода, сохранённая `entitled_version` поднимается до последнего релиза проекта, вышедшего не позже нового `updates_until`; активационный ключ SHALL сохраняться прежним. Отозванная лицензия MUST NOT продлеваться оплатой периода — она остаётся `revoked` (отзыв необратим). Уже выданные установкам токены SHALL получать новые entitlements при очередном refresh.

#### Scenario: Успешное продление сдвигает срок лицензии

- **WHEN** платёж продления подписки организации на лицензионный план подтверждён
- **THEN** период подписки продлён, `updates_until` лицензии равен новому концу периода, `entitled_version` поднята по каталогу релизов, ключ прежний

#### Scenario: Неуспешное продление не трогает лицензию

- **WHEN** платёж продления подписки организации неуспешен
- **THEN** лицензия не изменяется; она остаётся `active` со своим текущим окном обновлений

#### Scenario: Отозванная лицензия не воскресает оплатой

- **WHEN** платёж продления подтверждён по подписке организации, чья лицензия по этому плану отозвана
- **THEN** период подписки продлевается, но лицензия остаётся `revoked` без изменений

### Requirement: Отмена подписки не отзывает лицензию

Отмена, приостановка или удаление подписки MUST NOT отзывать или изменять лицензию: лицензия бессрочна, установки продолжают проходить активацию и refresh, замирает только окно обновлений — `updates_until` перестаёт сдвигаться, и после его истечения новые релизы становятся недоступны (кроме security-патчей разрешённых трейнов). Отзыв лицензии SHALL оставаться отдельным ручным действием оператора (см. `licensing/license-keys`) и MUST NOT изменять подписку.

#### Scenario: Лицензия доживает до конца оплаченного периода

- **WHEN** организация отменяет подписку, и оплаченный период истекает
- **THEN** лицензия остаётся `active`, refresh установок продолжает выдавать валидные токены, а проверка обновлений не предлагает релизы, вышедшие после `updates_until`

#### Scenario: Ручной отзыв при живой подписке

- **WHEN** оператор отзывает лицензию организации с активной подпиской
- **THEN** токены по лицензии выдаются со `status: revoked`, подписка при этом не изменяется
