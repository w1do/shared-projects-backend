# licensing/license-keys Specification

## Purpose

Perpetual-лицензии self-hosted-поставок: Ed25519-пара проекта, активационный ключ с хэш-хранением, entitlements-снимок (edition, фичи, версия права), окно обновлений и продление — лицензия бессрочна, оплачивается только доступ к новым версиям.

## Requirements

### Requirement: Ключевая пара подписи проекта

Система SHALL поддерживать одну активную Ed25519-пару ключей подписи на проект: пара генерируется автоматически при первой операции, требующей подписи; приватный ключ SHALL храниться только в зашифрованном виде и никогда не возвращаться ни одним API-ответом; публичный ключ SHALL быть доступен через admin-эндпоинт под правом `pay.licensing.manage` для встраивания в поставку.

#### Scenario: Получение публичного ключа проекта

- **WHEN** оператор с правом `pay.licensing.manage` запрашивает публичный ключ проекта
- **THEN** ответ содержит публичный ключ (при отсутствии пары она предварительно генерируется); приватный ключ в ответе отсутствует

#### Scenario: Приватный ключ не покидает хранилище

- **WHEN** любой API-эндпоинт модуля лицензирования возвращает данные
- **THEN** приватный ключ проекта не содержится в ответе ни в открытом, ни в зашифрованном виде

### Requirement: Выпуск лицензии

Система SHALL позволять оператору с правом `pay.licensing.manage` выпустить лицензию для пары организация+план своего проекта с указанием: даты окончания окна обновлений `updates_until` (в будущем), лимита установок `max_installations` (целое ≥ 1, по умолчанию 1), опциональной `entitled_version` (SemVer) и опциональной заметки. При выпуске система SHALL: сгенерировать глобально уникальный активационный ключ формата `LIC-XXXX-XXXX-XXXX-XXXX` (16 символов алфавита `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` — без `0`, `O`, `1`, `I` — из криптографического ГСЧ); сохранить только `sha256`-хэш нормализованного ключа (верхний регистр, без пробелов) и его префикс для поиска в админке — сам ключ SHALL NOT храниться и SHALL NOT попадать в логи; зафиксировать entitlements: `edition` = `code` плана, снимок эффективного набора кодов фич (базовые фичи плана + переопределения организации), `entitled_version` (если не передана — версия последнего релиза проекта на момент выпуска, при отсутствии релизов — пусто). Полный ключ SHALL возвращаться только в ответе на выпуск — единственный раз. Выпуск для организации или плана другого проекта SHALL быть невозможен.

#### Scenario: Успешный выпуск лицензии

- **WHEN** оператор с правом `pay.licensing.manage` выпускает лицензию для организации и плана текущего проекта с `updates_until` в будущем
- **THEN** создаётся лицензия со статусом `active`, ответ содержит полный ключ формата `LIC-XXXX-XXXX-XXXX-XXXX`, а в хранилище остаются только его `sha256`-хэш и префикс

#### Scenario: Ключ показывается один раз

- **WHEN** оператор после выпуска запрашивает список или просмотр лицензии
- **THEN** ответ содержит только префикс ключа; полный ключ недоступен ни одним эндпоинтом

#### Scenario: Фичи фиксируются на момент выпуска

- **WHEN** после выпуска лицензии план получает новую базовую фичу
- **THEN** entitlements ранее выпущенной лицензии не изменяются; новая фича попадает только в лицензии, выпущенные после изменения

#### Scenario: Выпуск без права manage недоступен

- **WHEN** оператор без права `pay.licensing.manage` выпускает лицензию
- **THEN** система возвращает ошибку доступа в стандартном envelope

### Requirement: Статусы и отзыв лицензии

Лицензия SHALL иметь ровно два статуса: `active` и `revoked` (`revoked` — при заполненном `revoked_at`). Понятия «истёкшая лицензия» SHALL NOT существовать: истечение `updates_until` не меняет статус — лицензия бессрочна, закрывается только окно обновлений. Оператор с правом `pay.licensing.manage` SHALL иметь возможность отозвать лицензию (возврат средств, кража ключа); отзыв необратим, повторный отзыв SHALL отклоняться доменной ошибкой валидации.

#### Scenario: Истечение срока

- **WHEN** наступает момент позже `updates_until` неотозванной лицензии
- **THEN** лицензия остаётся в статусе `active`; меняется только доступность обновлений (см. `licensing/releases`)

#### Scenario: Отзыв лицензии

- **WHEN** оператор с правом `pay.licensing.manage` отзывает активную лицензию
- **THEN** лицензия получает статус `revoked`; выдаваемые по ней токены содержат `status: revoked` (см. `licensing/license-activation`)

#### Scenario: Повторный отзыв отклоняется

- **WHEN** оператор отзывает уже отозванную лицензию
- **THEN** система возвращает доменную ошибку валидации, `revoked_at` не изменяется

### Requirement: Список и просмотр лицензий

Система SHALL предоставлять admin-эндпоинты списка и просмотра лицензий проекта под правом `pay.licensing.view`: организация, план, префикс ключа, `edition`, `entitled_version`, `updates_until`, `max_installations`, число активных установок, статус, `issued_at`. Список SHALL поддерживать пагинацию и фильтрацию по организации и статусу (`active`/`revoked`). Просмотр лицензии SHALL включать её установки (см. `licensing/license-activation`).

#### Scenario: Список лицензий с фильтром по организации

- **WHEN** оператор с правом `pay.licensing.view` запрашивает лицензии конкретной организации
- **THEN** ответ содержит только лицензии этой организации текущего проекта с их entitlements, префиксами ключей и статусами

#### Scenario: Полный ключ в списках отсутствует

- **WHEN** оператор запрашивает список или просмотр лицензий
- **THEN** ни один ответ не содержит полного активационного ключа

### Requirement: Продление окна обновлений

Система SHALL позволять оператору с правом `pay.licensing.manage` продлить лицензию: `updates_until` сдвигается на переданную дату (SHALL быть позже текущего значения), а сохранённая `entitled_version` поднимается до версии последнего релиза проекта, вышедшего не позже нового `updates_until` (если таких релизов нет или сохранённая версия выше — она не меняется). Продление MUST NOT менять активационный ключ и MUST NOT применяться к отозванной лицензии (доменная ошибка валидации). Право на уже купленные версии MUST NOT отбираться: `entitled_version` никогда не понижается.

#### Scenario: Продление сдвигает окно и поднимает версию

- **WHEN** оператор продлевает лицензию с `updates_until` в прошлом, передав новую дату, к которой в проекте вышли более новые релизы
- **THEN** `updates_until` устанавливается в новую дату, `entitled_version` поднимается до последнего релиза, вышедшего не позже неё, ключ остаётся прежним

#### Scenario: Дата не позже текущей отклоняется

- **WHEN** оператор передаёт дату продления, не превышающую текущий `updates_until`
- **THEN** система возвращает доменную ошибку валидации, лицензия не изменяется

#### Scenario: Отозванная лицензия не продлевается

- **WHEN** оператор продлевает отозванную лицензию
- **THEN** система возвращает доменную ошибку валидации, лицензия остаётся `revoked`
