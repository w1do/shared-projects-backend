# licensing/plans Specification

## Purpose

Планы лицензионной поставки (тарифы self-hosted-дистрибутива) и их фичи, включая пер-организационные переопределения, — определяют, какая функциональность разрешена лицензией. Отдельны от подписочных планов `payments/*`.

## Requirements

### Requirement: Модель плана лицензионной поставки

Система SHALL хранить планы лицензионной поставки с атрибутами: `code` (машинный ключ, kebab-case), `name` (отображаемое имя), `project_id` и опциональной ценой периода: `price_minor` (минорные единицы), `currency`, `interval` — либо все три заполнены, либо все три пусты. `code` SHALL быть уникален в пределах проекта. План с заполненной ценой SHALL быть доступен как предмет подписки (см. `licensing/license-subscriptions`); план без цены — только для ручного выпуска лицензий. Планы лицензирования SHALL храниться отдельно от подписочных планов биллинга и не влиять на них.

#### Scenario: Уникальность code в проекте

- **WHEN** оператор создаёт план с `code`, уже существующим в текущем проекте
- **THEN** система возвращает ошибку валидации, дубликат не создаётся

#### Scenario: Одинаковый code в разных проектах допустим

- **WHEN** в двух разных проектах создаются планы с одинаковым `code`
- **THEN** оба плана сохраняются независимо

#### Scenario: Частично заполненная цена отклоняется

- **WHEN** оператор сохраняет план с `price_minor`, но без `currency` или `interval`
- **THEN** система возвращает ошибку валидации, план не сохраняется

### Requirement: Фичи плана и переопределения для организаций

Система SHALL хранить фичи плана с атрибутами: `plan_id`, `organization_id` (nullable), `code` (машинный ключ фичи), `name` (название фичи). Запись с `organization_id = NULL` SHALL считаться базовой фичей плана; запись с заполненным `organization_id` — дополнительной фичей этого плана для конкретной организации. Эффективный набор фич для пары план+организация SHALL равняться объединению базовых фич плана и переопределений этой организации. Комбинация `plan_id` + `organization_id` + `code` SHALL быть уникальна.

#### Scenario: Эффективный набор фич организации

- **WHEN** у плана есть базовые фичи `api-access` и `sso`, а организации добавлено переопределение `audit-log` по этому плану
- **THEN** эффективный набор фич этой организации по плану — `api-access`, `sso`, `audit-log`; для организаций без переопределений — только `api-access`, `sso`

#### Scenario: Дубликат фичи отклоняется

- **WHEN** оператор добавляет плану базовую фичу с `code`, уже существующим среди его базовых фич
- **THEN** система возвращает ошибку валидации, дубликат не создаётся

### Requirement: Admin CRUD планов и фич

Система SHALL предоставлять admin-эндпоинты списка и просмотра планов (включая их фичи) под правом `pay.licensing.view`, а создания, изменения и удаления планов и их фич — под правом `pay.licensing.manage`. Все операции SHALL действовать только в пределах текущего проекта.

#### Scenario: Просмотр плана с фичами

- **WHEN** оператор с правом `pay.licensing.view` запрашивает план
- **THEN** ответ содержит атрибуты плана, его базовые фичи и переопределения по организациям

#### Scenario: Управление фичами без права manage недоступно

- **WHEN** оператор без права `pay.licensing.manage` добавляет фичу плану
- **THEN** система возвращает ошибку доступа в стандартном envelope

### Requirement: Защита плана с лицензиями от удаления

Система SHALL запрещать удаление плана, на который выпущена хотя бы одна лицензия (в любом статусе), возвращая доменную ошибку валидации.

#### Scenario: Удаление плана с лицензиями отклоняется

- **WHEN** оператор с правом `pay.licensing.manage` удаляет план, по которому выпущена лицензия
- **THEN** система возвращает доменную ошибку валидации, план сохраняется

#### Scenario: Удаление неиспользуемого плана

- **WHEN** оператор с правом `pay.licensing.manage` удаляет план без лицензий
- **THEN** план удаляется вместе с его фичами и переопределениями
