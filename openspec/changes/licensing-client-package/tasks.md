# Tasks: licensing-client-package

Все задачи выполняются в отдельном репозитории пакета `shared/licensing` (см. design.md, Д1); в этом монорепо код не появляется. Дельта-спеки изменения — приёмочные критерии пакета.

## 1. Каркас пакета

- [ ] 1.1 Создать репозиторий пакета: `composer.json` (`shared/licensing`, PHP ≥ 8.3, `ext-sodium`, `illuminate/support` ≥ 11), плоский namespace `Shared\Licensing`, сервис-провайдер в корне `src/`; проверить `composer validate` и установку в пустое Laravel-приложение
- [ ] 1.2 Публикуемые `config/licensing.php` (server, public_key-литерал, trial_days=30, refresh interval, state_cache_seconds=60, app_version, excluded routes, route активации, schedule on/off) и миграция `license_state` (одна строка: license_key encrypted, install_id char(64), token, first_run_at, checked_at, clock_guard_at); проверить `vendor:publish` и `migrate` в тестовом приложении
- [ ] 1.3 Каркас тестов: Orchestra Testbench + Pest, генерация локальной Ed25519-пары и подписанных токенов-фикстур в хелперах; smoke-тест «пакет грузится, конфиг читается» зелёный

## 2. Состояние лицензии (спека licensing-client/license-state)

- [ ] 2.1 Репозиторий состояния: ленивое создание единственной записи, генерация `install_id` из криптографического ГСЧ, фиксация `first_run_at`, шифрование ключа; тесты: install_id стабилен, `cache:clear` не сбрасывает состояние, ключ в БД не в открытом виде
- [ ] 2.2 Верификатор токена: паддинг-толерантный b64url-декод, `sodium_crypto_sign_verify_detached` по сырым байтам, строгое `v === 1`, сверка install_id и нормализованного домена (lowercase, без `www.`, host из URL приложения), допуск неизвестных полей payload; юнит-тесты: валидный токен, чужая подпись, порча байта, чужой install_id/домен, нормализация регистров и `www.`
- [ ] 2.3 Машина состояний: шесть состояний в порядке ТЗ 3.3 (clock guard → токен → валидность → revoked → версия → окно), протухший `expires_at` токена состояние не меняет; кэш через `Cache::remember` с TTL из конфига, без static; тесты — вся матрица ТЗ 3.11 с заморозкой времени, включая «часы назад на сутки → unlicensed» и «смена состояния видна не позже TTL»

## 3. Клиент сервера лицензий (спека licensing-client/activation)

- [ ] 3.1 HTTP-клиент контракта: base URL из конфига, таймаут, разбор конвертов `{data}`/`{error:{code,message}}`, типизированные результаты и ошибки с кодами ТЗ 1.7; contract-тесты форм запросов/ответов на `Http::fake`
- [ ] 3.2 Активация: POST activate, проверка подписи пришедшего токена ДО сохранения, сохранение ключа+токена, сброс кэша; тесты: успех → licensed, 409 лимит → состояние не тронуто, токен с плохой подписью от сервера → отказ без сохранения
- [ ] 3.3 Fail-safe refresh: не чаще интервала, любой неуспех (сеть/4xx/5xx/429/плохая подпись) → false без исключений и без изменения токена; revoked-токен на 200 сохраняется; тесты: «сервер недоступен + expires_at в прошлом → состояние не деградирует», «revoked доносится refresh'ем»
- [ ] 3.4 Деактивация: POST deactivate, очистка локальных ключа/токена, возврат к правилам триала; тест сценария переезда (deactivate → активация нового install_id в пределах лимита на `Http::fake`)
- [ ] 3.5 Офлайн-цикл: запись файла-запроса JSON `{install_id, domain, app_version, requested_at}` и установка токен-файла (содержимое — токен строкой) с проверкой подписи и принадлежности до сохранения; тесты: полный офлайн-цикл без сети, чужой токен-файл отклонён
- [ ] 3.6 Проверка обновлений: POST updates/check, трансляция `latest_entitled`/`latest_available`/`image`/`changelog_url`/`security_update` и ошибок 403/404; тест «клиент видит, что отстал» и «недоступный сервер → отрицательный результат без исключений»

## 4. Enforcement (спека licensing-client/enforcement)

- [ ] 4.1 Middleware: таблица поведения по шести состояниям, 402 с конвертом ошибки для JSON / redirect на конфигурируемый маршрут для web, атрибуты-признаки для пропускаемых состояний, список исключённых маршрутов; feature-тесты каждого состояния, исключённых маршрутов и подсказки версий для `version_not_entitled`
- [ ] 4.2 Гейты: `allows(feature)`/`edition()`/`isOperational()` по снимку payload через кэш состояния (trial — всё, unlicensed/revoked — ничего); тесты: фича из снимка/вне снимка, триал, отзыв
- [ ] 4.3 Водяной знак: стабильный короткий идентификатор от `install_id` без утечки ключа; тест стабильности между перезапусками и отсутствия ключа в значении

## 5. CLI и расписание (спека licensing-client/cli)

- [ ] 5.1 Команды `license:activate {key}`, `license:status` (офлайн), `license:refresh` (SUCCESS+warning при недоступном сервере), `license:deactivate`, `license:updates`; тесты кодов выхода и вывода, ключ не попадает в вывод/логи
- [ ] 5.2 Команды офлайн-цикла `license:offline-request {path?}` и `license:offline-install {file}`; тест полного цикла через файлы во временном каталоге
- [ ] 5.3 Регистрация ежесуточного refresh в планировщике (withoutOverlapping + случайный разброс, отключаемо конфигом); тесты регистрации и отключения

## 6. Качество и выпуск

- [ ] 6.1 Качественный гейт пакета: Pint + PHPStan (уровень как в монорепо) + полный Pest зелёные в CI репозитория пакета
- [ ] 6.2 README интеграции: подключение, публикация конфига (public_key и app_version — в код/из build-arg, не из env), middleware и исключённые маршруты, требование 3–5 независимых точек `allows()`, офлайн-цикл, Octane-замечания
- [ ] 6.3 Интеграционная проверка против dev-стенда сервера лицензий этого монорепо: выпуск лицензии в консоли → `license:activate` → `license:status` → `license:refresh` → `license:updates` → `license:deactivate` и офлайн-цикл через консоль вендора; все шаги успешны
- [ ] 6.4 Публикация пакета в shared Composer-реестре и установка в первую поставку; после выпуска — синк/архивация этого изменения (`/opsx:archive licensing-client-package`), чтобы спеки `licensing-client/*` стали main-спеками
