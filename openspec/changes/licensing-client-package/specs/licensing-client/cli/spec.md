# licensing-client/cli Specification (delta)

## Purpose

Консольные операции лицензии для операторов поставки и автоматизации: активация, статус, refresh, деактивация, проверка обновлений и офлайн-цикл — единственный интерфейс пакета помимо программного API (headless).

## ADDED Requirements

### Requirement: Команды операций лицензии

Пакет SHALL предоставлять artisan-команды: `license:activate {key}` — активация ключом; `license:status` — текущее состояние, редакция, разрешённая версия, фичи, окно обновлений и оставшиеся дни триала, работает полностью офлайн; `license:refresh` — принудительный refresh; `license:deactivate` — деактивация установки с подтверждением; `license:updates` — проверка обновлений с выводом доступной и последней существующей версий; `license:offline-request {path?}` — запись файла-запроса установки; `license:offline-install {file}` — установка токен-файла. `license:refresh` при недоступности сервера SHALL завершаться кодом успеха с предупреждением — не ошибкой, чтобы не поднимать ложные алёрты планировщика; активационный ключ MUST NOT выводиться в вывод команд и логи планировщика.

#### Scenario: Активация из терминала

- **WHEN** оператор выполняет `license:activate` с валидным ключом
- **THEN** команда сообщает об успехе и новое состояние; `license:status` показывает `licensed`

#### Scenario: Статус без сети

- **WHEN** `license:status` выполняется при недоступном сервере лицензий
- **THEN** команда выводит состояние и entitlements по сохранённому токену без обращений к сети

#### Scenario: Refresh при недоступном сервере

- **WHEN** `license:refresh` выполняется при недоступном сервере
- **THEN** команда завершается кодом успеха с предупреждением, сохранённый токен не тронут

#### Scenario: Офлайн-цикл из терминала

- **WHEN** оператор выполняет `license:offline-request`, передаёт файл вендору и устанавливает полученный токен-файл через `license:offline-install`
- **THEN** установка активирована без сетевых запросов, `license:status` показывает `licensed`

### Requirement: Расписание фонового refresh

Пакет SHALL регистрировать в планировщике хоста ежесуточный `license:refresh` без перекрытия запусков и со случайным разбросом по времени суток (защита сервера лицензий от синхронного всплеска всех установок). Регистрация SHALL отключаться конфигом — хост может планировать refresh сам.

#### Scenario: Разброс по времени суток

- **WHEN** несколько установок работают с одинаковым расписанием по умолчанию
- **THEN** их refresh-запросы распределяются по времени, а не приходят одновременно

#### Scenario: Отключение штатного расписания

- **WHEN** хост отключает регистрацию расписания конфигом
- **THEN** пакет не добавляет задачу в планировщик, ручной и программный refresh продолжают работать
