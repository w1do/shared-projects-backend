# licensing-client/enforcement Specification (delta)

## Purpose

Применение состояния лицензии в хост-приложении: HTTP-middleware с таблицей поведения по состояниям, программные гейты фич и редакции для независимых точек проверки и водяной знак установки — без собственного UI (headless).

## ADDED Requirements

### Requirement: Middleware по состояниям

Пакет SHALL предоставлять HTTP-middleware со строгой таблицей поведения: `licensed` — пропустить; `updates_expired` — пропустить, отдав хосту признак «обновления недоступны»; `trial` — пропустить, отдав число оставшихся дней; `unlicensed` и `revoked` — заблокировать; `version_not_entitled` — заблокировать, отдав требуемую версию. Блокировка SHALL различать тип запроса: для JSON-запросов — ответ 402 в конверте ошибки с машинным кодом состояния и русским сообщением; для web-запросов — редирект на настраиваемый маршрут активации хоста. Маршруты из настраиваемого списка исключений (эндпоинты активации хоста) SHALL пропускаться при любом состоянии — иначе активироваться невозможно. Признаки состояния SHALL быть доступны хосту программно для баннеров и счётчиков.

#### Scenario: Истёкшее окно пропускает с баннером

- **WHEN** запрос проходит middleware в состоянии `updates_expired`
- **THEN** запрос выполняется, хосту доступен признак «обновления недоступны» для показа баннера

#### Scenario: Незалицензированный JSON-запрос

- **WHEN** JSON-запрос приходит в состоянии `unlicensed`
- **THEN** ответ — 402 с машинным кодом состояния и русским сообщением в конверте ошибки

#### Scenario: Маршруты активации доступны всегда

- **WHEN** запрос к маршруту из списка исключений приходит в состоянии `unlicensed`
- **THEN** запрос пропускается — активация возможна из заблокированного состояния

#### Scenario: Версия выше оплаченной блокируется с подсказкой

- **WHEN** запрос приходит в состоянии `version_not_entitled`
- **THEN** блокировка содержит текущую и максимально разрешённую версии — хост может предложить откат или продление

### Requirement: Гейты фич и редакции

Пакет SHALL предоставлять программный API проверки прав: доступность фичи (по снимку `features` последнего валидного токена), редакция (`edition`) и общая работоспособность. В состоянии `trial` все фичи SHALL считаться доступными; в состояниях `unlicensed` и `revoked` — недоступными; в `licensed` и `updates_expired` — по снимку токена. API SHALL быть пригоден для нескольких независимых точек проверки в разных слоях хоста (policy, командный слой, ресурсы) — одна точка снимается одной строкой, поэтому единственной проверки MUST NOT быть достаточно по проекту интеграции.

#### Scenario: Фича из снимка доступна

- **WHEN** токен несёт фичу `warehouse` и хост проверяет её доступность в состоянии `licensed`
- **THEN** проверка возвращает разрешение

#### Scenario: Фича вне снимка недоступна

- **WHEN** хост проверяет фичу, отсутствующую в `features` токена
- **THEN** проверка возвращает отказ

#### Scenario: Триал открывает все фичи

- **WHEN** хост проверяет любую фичу в состоянии `trial`
- **THEN** проверка возвращает разрешение

### Requirement: Водяной знак установки

Пакет SHALL предоставлять стабильный короткий идентификатор установки (производный от `install_id`), пригодный для вставки в покидающие систему артефакты: метаданные экспортов, документы, служебные заголовки. Идентификатор SHALL быть одинаковым между вызовами и перезапусками; активационный ключ или его фрагменты MUST NOT входить в водяной знак.

#### Scenario: Водяной знак стабилен и безопасен

- **WHEN** водяной знак запрашивается дважды с перезапуском приложения между вызовами
- **THEN** значения совпадают и не содержат активационного ключа
