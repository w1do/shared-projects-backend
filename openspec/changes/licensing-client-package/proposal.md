# Proposal: licensing-client-package

## Why

Серверная часть лицензирования (perpetual-модель: активационные ключи, Ed25519-токены с entitlements, учёт установок, каталог релизов — изменение `licensing-perpetual-model`) готова, но у self-hosted-поставок нет клиентской части: нечем активировать ключ, проверять токен, держать состояние лицензии и блокировать неоплаченные сценарии. Нужен переиспользуемый Laravel-пакет `licensing` (Composer-имя `shared/licensing`), который любой бекенд поставки подключает как зависимость и получает полный клиентский контур по ТЗ `lic.md` (часть 3). Пакет разрабатывается в отдельном репозитории и публикуется в shared-реестре — это изменение фиксирует только спецификацию и план реализации; кода в текущем монорепо не появляется.

## What Changes

- Новый standalone Laravel-пакет `shared/licensing` (namespace `Shared\Licensing`) для бекендов self-hosted-поставок; полностью **headless**: сервис, middleware, artisan-команды и события — без каких-либо экранов, вью и Filament (UI рисует хост-приложение).
- Локальное состояние лицензии: таблица `license_state` (одна строка), `install_id` машины, шифрованный ключ, последний валидный токен, старт триала, монотонная отметка против перевода часов назад.
- Вычисление шести состояний инсталла (`licensed`, `updates_expired`, `trial`, `unlicensed`, `version_not_entitled`, `revoked`) строго по ТЗ 1.2/3.3: офлайн-проверка Ed25519-подписи токена публичным ключом, вшитым в код; истечение окна обновлений и протухший TTL токена работу не блокируют.
- Клиент серверного контракта `/api/v1/pay/licensing`: активация ключом, ежесуточный fail-safe refresh, деактивация при переезде, проверка обновлений `updates/check`; офлайн-активация файлом-запросом и токен-файлом для закрытых контуров.
- Enforcement: middleware `EnsureLicense` с конфигурируемой реакцией на блокирующие состояния и гейты фич/редакции `allows()` для независимых точек проверки в коде хоста; водяной знак `install_id` для исходящих артефактов.
- CLI: `license:activate`, `license:refresh`, `license:status`, `license:deactivate`, `license:updates`, `license:offline-request`, `license:offline-install` + регистрация ежесуточного refresh в планировщике.
- Октейн-безопасность: состояние только в БД + кэш с TTL, никаких static-кэшей и синглтонов с состоянием.

## Capabilities

### New Capabilities

- `licensing-client/license-state`: локальное состояние лицензии поставки — хранение `license_state`, генерация `install_id`, офлайн-проверка токена, алгоритм вычисления шести состояний, защита от перевода часов, кэширование и Octane-инварианты.
- `licensing-client/activation`: обмен с сервером лицензий — активация ключом, fail-safe refresh, деактивация, проверка обновлений, офлайн-активация файлами; конфигурация пакета (адрес сервера, публичный ключ в коде, версия приложения из сборки).
- `licensing-client/enforcement`: применение состояния — middleware `EnsureLicense` с таблицей поведения по состояниям, гейты фич и редакции, водяные знаки `install_id`.
- `licensing-client/cli`: artisan-команды операций лицензии и расписание фонового refresh.

### Modified Capabilities

Нет: серверный контракт (`licensing/license-activation`, `licensing/releases`) не меняется — пакет только потребляет его.

## Impact

- **Код текущего монорепо**: не меняется. Артефакты этого изменения — спецификация и план для отдельного репозитория пакета `shared/licensing`; после реализации пакет публикуется в shared Composer-реестре.
- **Целевой стек пакета**: PHP ≥ 8.3, `ext-sodium`, Laravel ≥ 11 (совместимость с Octane обязательна); dev-зависимости — Orchestra Testbench + Pest для тестов пакета.
- **Контракт-зависимость**: публичный HTTP-контракт сервера лицензий из `licensing-perpetual-model` (эндпоинты `license/activate|refresh|deactivate`, `updates/check`, формат токена `b64url(payload).b64url(signature)`, конверты `{data}` / `{error:{code,message}}`, коды ошибок ТЗ 1.7). Изменения серверного контракта потребуют синхронного релиза пакета.
- **Хост-приложения поставок**: подключают пакет, публикуют конфиг/миграцию, вешают `EnsureLicense` на защищаемые маршруты и расставляют гейты `allows()`; экраны активации и баннеры реализуют сами поверх API пакета.
