# Design: licensing-client-package

## Context

Мотивация — в `proposal.md`. Серверная сторона готова (`licensing-perpetual-model`, спеки `licensing/license-activation` и `licensing/releases`): публичные эндпоинты `/api/v1/pay/licensing/license/activate|refresh|deactivate` и `/updates/check`, токен `b64url(payload).b64url(signature)` (Ed25519 detached по сырым байтам, payload v1), конверты `{data}` / `{error:{code,message}}`, коды ошибок ТЗ 1.7, throttle 60/мин. Эталон клиентской части — ТЗ `lic.md`, часть 3, с двумя отступлениями по решению владельца: пакет полностью headless (без Filament/blade — только сервис, middleware, CLI) и реализуется в отдельном репозитории с публикацией в shared Composer-реестре. Код в текущем монорепо не появляется — артефакты этого изменения переносятся в репозиторий пакета как задание.

## Goals / Non-Goals

**Goals:**

- Один пакет `shared/licensing`, подключаемый любым Laravel-бекендом поставки: `composer require` + публикация конфига и миграции + middleware на маршруты + гейты в коде.
- Полная работоспособность в закрытом контуре (офлайн-активация, годовой токен) и при длительной недоступности сервера лицензий.
- Octane-безопасность из коробки.

**Non-Goals:**

- Любой UI: экраны активации, баннеры, разделы панели — ответственность хост-приложения поверх программного API пакета.
- Доступ к Docker Registry / скачивание образов (часть 2.5 ТЗ) — отдельная задача registry-доступа.
- Изменения серверной части: контракт потребляется как есть.
- Trial-механика на сервере: триал — чисто локальное состояние установки.

## Decisions

### Д1. Плоская структура библиотеки, не four-layer DDD

Пакет живёт в чужих стеках, канон монорепо (`packages/cms/*`) к нему не применяется. Структура — обычная Laravel-библиотека: `src/` с плоским namespace `Shared\Licensing` (сервис, verifier, http-клиент, `Middleware/`, `Commands/`), сервис-провайдер в корне `src/`, публикуемые `config/licensing.php` и миграция.
*Альтернатива* — повторить four-layer: отвергнуто, для пакета из ~15 классов это шум, а гейты монорепо на него всё равно не распространяются.

### Д2. Состояние — одна строка в БД, ключ шифрованный

Таблица `license_state` (одна запись): `license_key` (encrypted-cast), `install_id` char(64), `token` text, `first_run_at`, `checked_at`, `clock_guard_at`. Запись создаётся лениво при первом обращении; `install_id` = `bin2hex(random_bytes(32))`, `first_run_at` фиксируется при создании записи. БД, а не кэш — `cache:clear` не должен сбрасывать триал и лицензию (ТЗ 3.2).

### Д3. Верификация токена — отдельный чистый компонент

Разбор и проверка в одном месте: паддинг-толерантный b64url-декод, `sodium_crypto_sign_verify_detached` по сырым байтам payload, строгое `v === 1`, допуск неизвестных полей (forward-совместимость с v1-расширениями). Публичный ключ — литерал опубликованного конфиг-файла; env-канал не читается (Д7 ТЗ: клиент не должен уметь подставить свой ключ конфигурацией окружения).

### Д4. Состояние считает клиент, серверному hint не доверяем

Поле `state` из ответов activate/refresh — только подсказка; локальный алгоритм (порядок из ТЗ 3.3: часы → токен → подпись/принадлежность → revoked → версия → окно) единственный источник правды. Результат — `Cache::remember` с TTL из конфига (60с), никаких static/синглтонов с состоянием (Octane, ТЗ 3.7).

### Д5. Сеть только в явных операциях, refresh — fail-safe

HTTP-клиент (Laravel `Http`, таймаут ~5с, без ретраев) вызывается только из команд и программных операций — middleware и гейты работают строго по локальному состоянию. Любой неуспех refresh (сеть, 4xx/5xx/429, невалидная подпись) → `false`, сохранённый токен не трогается. Единственный канал деградации — валидный ответ сервера: revoked-токен на 200 заменяет сохранённый. Ответ 404 `unknown_installation` (копию отозвали на сервере) токен не затирает — осознанно по ТЗ: блокировка отозванной копии обеспечивается недоступностью обновлений и registry, не самоуничтожением клиента.

### Д6. Блокировка в middleware: 402 для JSON, redirect для web

`unlicensed`/`revoked`/`version_not_entitled`: `expectsJson()` → 402 с конвертом `{error:{code,message}}` (код — имя состояния), иначе redirect на `config('licensing.routes.activate')`. Пропускаемые состояния кладут признаки (`updates_expired`, дни триала) в атрибуты запроса и доступны через сервис — хост рисует баннеры сам. Список исключённых маршрутов — конфиг (паттерны), проверяется до вычисления состояния.
*Альтернатива* — события/хуки-колбэки на каждое состояние: отвергнуто, конфиг + переопределение middleware хостом проще и предсказуемее.

### Д7. Гейты фич — по снимку payload

`allows(feature)`/`edition()` читают `features`/`edition` последнего валидного токена через тот же кэш состояния; `trial` = всё разрешено, `unlicensed`/`revoked` = всё запрещено. Точек проверки в хосте должно быть несколько (ТЗ 3.8) — это требование интеграции, пакет даёт дешёвый API.

### Д8. Офлайн-цикл — те же файлы, что у консоли вендора

Файл-запрос — JSON `{install_id, domain, app_version, requested_at}` (ровно формат, который принимает офлайн-активация консоли сервера); токен-файл — токен строкой (ровно то, что консоль отдаёт на скачивание как `license-token-*.lic`). Никаких собственных конвертов — форматы уже зафиксированы серверной стороной.

### Д9. Тесты — Testbench + локальная sodium-пара

Orchestra Testbench + Pest; сервер мокается `Http::fake`, токены в тестах подписываются локально сгенерированной парой, публичная половина подставляется в конфиг. Обязательная матрица — ТЗ 3.11 (все шесть состояний, чужая подпись/домен, перевод часов, недоступный сервер с протухшим TTL, `cache:clear`). Заморозка времени для триала и clock guard.

### Д10. Версия приложения — из сборки

Пакет читает `config('licensing.app_version')`; хост обязан заполнять его значением, зашитым на сборке образа (build-arg → конфиг), а не из env времени выполнения — иначе версия тривиально подделывается (ТЗ 3.1). Требование фиксируется в README интеграции.

## Risks / Trade-offs

- [Серверный контракт изменится] → клиентские contract-тесты фиксируют формы запросов/ответов; версия пакета связывается с версией контракта (`v: 1`), неизвестная версия payload → `unlicensed`.
- [Отозванная копия живёт на старом токене до его невалидности] → осознанный компромисс ТЗ (доступность важнее мгновенной блокировки); рычаг — registry и `updates/check`, отзыв всей лицензии доносится revoked-токеном при refresh.
- [Хост поставит единственную проверку и её вырежут] → README требует минимум 3–5 независимых точек `allows()` в разных слоях; водяной знак помогает расследованию тиражирования.
- [Часы контейнера дрейфуют легально (NTP-скачки)] → допуск 300с в clock guard; порог в конфиге.
- [Разъезд нормализации домена клиент/сервер] → правило зафиксировано в обеих спеках одинаково (lowercase, без `www.`, host из URL приложения); тест на совпадение включён в матрицу.

## Migration Plan

1. Создать репозиторий пакета `shared/licensing`, перенести артефакты этого изменения как задание (спеки — приёмочные критерии).
2. Реализовать по tasks.md, прогнать матрицу тестов ТЗ 3.11.
3. Интеграционная проверка против работающего сервера лицензий этого монорепо (dev-стенд): activate → refresh → updates/check → deactivate, офлайн-цикл через консоль вендора.
4. Публикация в shared Composer-реестре; подключение в первую поставку.
5. Rollback: пакет — зависимость поставки; откат = удаление зависимости, серверная сторона не затрагивается.
