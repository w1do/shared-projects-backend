# external-project-snapshot

## Purpose

Позволяет подключить к платформе уже работающий проект, живущий на своём сервере: его состав разделов, права и источники данных описываются загружаемым JSON-снапшотом, который платформа проверяет, версионирует и учитывает при сборке консоли наравне с манифестами собственных сервисов.

## ADDED Requirements

### Requirement: Загрузка снапшота внешнего проекта

Платформа SHALL принимать описание внешнего проекта как JSON-документ и связывать его с проектом. Документ MUST объявлять версию схемы, набор разделов и, для разделов с внешними данными, источник этих данных. Загрузка SHALL быть доступна только оператору с правом управления проектом; оператор без этого права MUST получать отказ.

#### Scenario: Корректный снапшот принят

- **WHEN** оператор с правом управления проектом загружает документ, соответствующий схеме
- **THEN** снапшот сохраняется как версия, привязанная к проекту, и становится активным

#### Scenario: Нет права на загрузку

- **WHEN** снапшот загружает оператор без права управления проектом
- **THEN** загрузка отклоняется, состав разделов проекта не меняется

### Requirement: Невалидный снапшот отклоняется целиком

Платформа SHALL проверять документ до сохранения: версию схемы, обязательные поля, уникальность ключей разделов, ссылки разделов на объявленные права и допустимость адресов источников данных. Документ, не прошедший проверку, MUST быть отклонён целиком с перечнем ошибок; частично применённых снапшотов быть не должно. Ранее активная версия при этом SHALL остаться активной.

#### Scenario: Документ с ошибками

- **WHEN** загружается документ с неизвестной версией схемы, дублирующимися ключами разделов или разделом без объявленного права
- **THEN** платформа отвечает перечнем ошибок, ничего не сохраняет, и проект продолжает работать на прежнем снапшоте

#### Scenario: Неподдерживаемая версия схемы

- **WHEN** документ объявляет версию схемы, которую платформа не поддерживает
- **THEN** загрузка отклоняется с явным указанием поддерживаемых версий

### Requirement: Версионирование и откат снапшота

Каждая успешная загрузка SHALL создавать новую версию снапшота, сохраняя предыдущие. Платформа SHALL показывать историю версий проекта с указанием, кто и когда загрузил каждую. Оператор с правом управления проектом SHALL иметь возможность вернуть любую сохранённую версию в активные; после отката состав разделов MUST соответствовать этой версии.

#### Scenario: Повторная загрузка создаёт версию

- **WHEN** оператор загружает снапшот проекта, у которого уже есть активный снапшот
- **THEN** создаётся новая версия, она становится активной, а предыдущая остаётся в истории

#### Scenario: Откат к предыдущей версии

- **WHEN** оператор возвращает предыдущую версию снапшота
- **THEN** активной становится она, и разделы проекта соответствуют её описанию

### Requirement: Разделы снапшота участвуют в составе консоли

Разделы активного снапшота SHALL попадать в состав консоли наравне с навигацией сервисов платформы. Раздел снапшота MUST отображаться только оператору, у которого есть объявленное для этого раздела право. Порядок и подписи разделов SHALL соответствовать описанию в снапшоте. Права, объявленные снапшотом, SHALL быть доступны для выдачи ролям проекта.

#### Scenario: Оператор с правом видит раздел

- **WHEN** оператору выдано право, объявленное для раздела снапшота
- **THEN** раздел присутствует в меню и открывается

#### Scenario: Оператор без права не видит раздел

- **WHEN** у оператора нет права, объявленного для раздела снапшота
- **THEN** раздел отсутствует в меню, а его прямое открытие приводит к странице отказа в доступе

#### Scenario: Снапшота нет

- **WHEN** у проекта нет активного снапшота
- **THEN** состав консоли определяется только сервисами платформы, дополнительных разделов не появляется

### Requirement: Снапшот изолирован проектом

Снапшот SHALL действовать только в пределах своего проекта. Разделы, права и источники данных одного проекта MUST NOT быть видны или доступны в другом проекте. Смена текущего проекта SHALL менять состав разделов на описанный снапшотом этого проекта.

#### Scenario: Разделы не протекают между проектами

- **WHEN** оператор, состоящий в двух проектах, открывает проект без снапшота
- **THEN** разделы снапшота другого проекта в меню отсутствуют
