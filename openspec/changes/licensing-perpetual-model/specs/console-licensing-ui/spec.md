# console-licensing-ui Specification (delta)

## MODIFIED Requirements

### Requirement: Раздел «Лицензирование» в панели

Панель SHALL предоставлять раздел «Лицензирование», объявленный за сервисом `licensing` и правом `pay.licensing.view`: пункт меню SHALL отображаться только при включённом сервисе и наличии права, прямой переход по адресу без доступа SHALL вести на страницу отказа. Раздел SHALL содержать вкладки организаций, планов, лицензий и релизов. Экраны SHALL собираться из существующих компонентов вёрстки без изменения дизайн-системы; тексты SHALL определяться ключами `console.*` с русскими значениями по умолчанию.

#### Scenario: Раздел виден при включённом сервисе и праве

- **WHEN** сервис `licensing` включён для проекта и у оператора есть право `pay.licensing.view`
- **THEN** пункт «Лицензирование» присутствует в меню и раздел открывается

#### Scenario: Выключение сервиса скрывает раздел сразу

- **WHEN** администратор выключает сервис `licensing` на экране управления сервисами
- **THEN** пункт «Лицензирование» исчезает из меню без повторного входа, а прямой адрес раздела ведёт на страницу отказа

#### Scenario: Тексты на русском по умолчанию

- **WHEN** оператор с локалью по умолчанию открывает раздел
- **THEN** заголовки, вкладки, колонки таблиц, кнопки, пустые состояния и сообщения отображаются на русском из реестра `console.*`

### Requirement: Управление лицензиями

Вкладка лицензий SHALL показывать лицензии проекта (организация, план, префикс ключа, `entitled_version`, `updates_until`, статус `active`/`revoked`, число установок из лимита) с фильтрами по организации и статусу и позволять оператору с правом `pay.licensing.manage`: выпустить лицензию (организация + план + дата окончания окна обновлений + лимит установок + опциональная версия), продлить лицензию (новая дата окна), отозвать лицензию с подтверждением, выполнить офлайн-активацию (загрузка файла-запроса, скачивание файла с токеном), просмотреть публичный ключ подписи проекта. Полный активационный ключ SHALL показываться один раз — сразу после выпуска, с возможностью копирования и предупреждением, что повторно он недоступен; в списках и просмотре SHALL отображаться только префикс. Просмотр лицензии SHALL показывать её установки (домен, версия, `last_seen_at`, статус) и позволять отозвать отдельную установку. Доменные ошибки (повторный отзыв, лимит установок) SHALL показываться сообщением.

#### Scenario: Выпуск лицензии

- **WHEN** оператор с правом manage выпускает лицензию, выбрав организацию, план, дату окна обновлений и лимит установок
- **THEN** показывается полный ключ `LIC-…` с возможностью копирования и предупреждением о единственном показе; после закрытия в списке отображается только префикс

#### Scenario: Отзыв лицензии

- **WHEN** оператор отзывает активную лицензию, подтвердив действие
- **THEN** лицензия отображается со статусом `revoked`

#### Scenario: Продление лицензии

- **WHEN** оператор продлевает лицензию, указав новую дату окна обновлений позже текущей
- **THEN** в списке лицензия отображается с новой датой `updates_until` и поднятой `entitled_version`

#### Scenario: Отзыв установки

- **WHEN** оператор в просмотре лицензии отзывает одну из установок, подтвердив действие
- **THEN** установка отображается отозванной, счётчик занятых слотов уменьшается

#### Scenario: Фильтр по статусу

- **WHEN** оператор применяет фильтр по статусу `revoked`
- **THEN** в списке только отозванные лицензии

### Requirement: Режим «только чтение» без права manage

Оператору с правом `pay.licensing.view` без `pay.licensing.manage` раздел SHALL быть доступен только на чтение: создание, изменение, удаление, выпуск, продление, отзыв лицензий и установок, офлайн-активация, управление релизами и просмотр ключа подписи SHALL быть недоступны в интерфейсе.

#### Scenario: Оператор без права manage

- **WHEN** раздел открывает оператор только с правом `pay.licensing.view`
- **THEN** списки организаций, планов, лицензий и релизов видны, изменяющие действия недоступны

## ADDED Requirements

### Requirement: Управление релизами

Вкладка релизов SHALL показывать каталог релизов проекта (версия, трейн, репозиторий образа, дата выхода, признак security, ссылка на changelog) списком с пагинацией и позволять оператору с правом `pay.licensing.manage` создавать, изменять и удалять релиз. Ошибки валидации (дубликат версии) SHALL показываться понятным сообщением.

#### Scenario: Создание релиза из консоли

- **WHEN** оператор с правом manage создаёт релиз, указав версию, трейн, репозиторий и дату выхода
- **THEN** релиз появляется в списке, оператор видит подтверждение

#### Scenario: Дубликат версии показывает ошибку

- **WHEN** оператор создаёт релиз с версией, уже существующей в проекте
- **THEN** форма показывает сообщение ошибки валидации, релиз не создаётся
