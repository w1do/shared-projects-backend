# translatable-content-fields

## Purpose

Делает поля сущностей контента переводимыми — имя категории хранит значения по локалям проекта при едином slug — не ломая существующий API и поведение дерева категорий.

## ADDED Requirements

### Requirement: Имя категории переводимо

Имя категории SHALL храниться как набор значений по локалям проекта (`name = {en: 'Categories', ru: 'Категории'}`) при едином slug. API категорий SHALL принимать имя и как строку (значение локали проекта по умолчанию), и как набор по локалям. Чтение SHALL отдавать набор целиком, а при запросе конкретной локали — её значение с откатом на локаль по умолчанию.

#### Scenario: Создание со строковым именем

- **WHEN** категория создаётся со строковым именем (как сейчас)
- **THEN** имя сохраняется значением локали проекта по умолчанию, API работает как прежде

#### Scenario: Создание с переводами

- **WHEN** категория создаётся с именем `{en: 'Categories', ru: 'Категории'}`
- **THEN** обе локали читаются обратно, slug один на категорию

#### Scenario: Чтение отсутствующей локали

- **WHEN** запрошено имя категории в локали, для которой перевода нет
- **THEN** возвращается значение локали проекта по умолчанию

### Requirement: Существующие данные и поведение сохраняются

Перевод поля в переводимую форму MUST сохранить существующие имена категорий (они становятся значением локали по умолчанию). Дерево, перемещение, удаление и привязка постов MUST вести себя без изменений. Панель SHALL продолжать отображать категории без правок логики видимости и перетаскивания.

#### Scenario: Миграция существующих имён

- **WHEN** выполняется миграция переводимого поля
- **THEN** каждая существующая категория читается с прежним именем в локали по умолчанию

#### Scenario: Дерево не затронуто

- **WHEN** после миграции выполняются операции дерева (создание, перемещение, удаление)
- **THEN** они ведут себя так же, как до изменения
