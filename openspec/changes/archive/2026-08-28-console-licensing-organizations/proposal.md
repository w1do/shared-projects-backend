# Proposal: console-licensing-organizations

## Why

Модуль лицензирования (организации-покупатели, планы поставки, лицензионные ключи) доступен только через API — в консоли нет ни одного экрана, оператор не может управлять им без ручных запросов. Сам модуль не представлен в реестре сервисов платформы: его admin-маршруты жёстко привязаны к сервису `pay` (`EnsureServiceEnabled:pay`), отдельно включить/выключить лицензирование на проект нельзя, и в экране «Сервисы проекта» оно отсутствует. Нужен консольный раздел лицензирования и штатный переключатель сервиса, включённый по умолчанию во всех проектах.

## What Changes

### Платформа (backend)

- Новый ключ сервиса `licensing` в реестре переключаемых сервисов (`ServiceName::toggleable()`: content, analytics, pay, **licensing**); переключение через существующий API `PUT /projects/{project}/services/{service}`.
- Собственный манифест лицензирования (ключ `licensing`, версия, навигация раздела консоли) с публикацией в auth-service; права **остаются** `pay.licensing.view|manage` — без переименований и миграций прав (декларация прав остаётся в `PayManifest`).
- Admin-маршруты модуля лицензирования переводятся с гейта `EnsureServiceEnabled:pay` на `EnsureServiceEnabled:licensing`; лицензирование и pay включаются/выключаются независимо. Публичная онлайн-валидация ключей от переключателя **не зависит** (выданные лицензии в поставках продолжают проверяться).
- «Включён по умолчанию»: в auth-service появляется механизм сервисов-по-умолчанию (конфиг-список, сейчас — только `licensing`): при создании проекта такие сервисы включаются автоматически; бэкфилл-миграция включает `licensing` во всех существующих проектах. Администратор может выключить его обычным переключателем.

### Консоль (frontend)

- Новый раздел «Лицензирование» (`/admin/licensing`) с вкладками:
  - **Организации** — список и CRUD анкеты организации-покупателя;
  - **Планы** — список и CRUD планов поставки, базовые фичи и пер-организационные переопределения;
  - **Лицензии** — список с фильтрами по организации и статусу, выпуск лицензии (организация + план + срок), отзыв, скачивание лицензионного файла, просмотр публичного ключа подписи проекта.
- Раздел виден при включённом сервисе `licensing` и праве `pay.licensing.view`; операции изменения — под правом `pay.licensing.manage` (без права — только чтение).
- Тумблер «Лицензирование» на экране Настройки → «Сервисы проекта».
- Тексты — через реестр `console.*` (русские значения по умолчанию); экраны собираются из существующих компонентов вёрстки; новые файлы `components/`/`app/` зеркалируются admin ↔ source-admin, API-обвязка — только в `frontends/admin`.
- Тесты: node-тесты (`section-access`, `console-texts`), e2e `console-navigation` (массив VISIBLE), обновление снимков маршрутов pay-service из-за смены middleware.

## Capabilities

### New Capabilities

- `licensing/service-registration`: лицензирование как переключаемый сервис платформы — ключ `licensing` в реестре, манифест с навигацией, гейт admin-маршрутов модуля по своему сервису, независимость от `pay`, включённость по умолчанию (новые и существующие проекты), публичная валидация вне переключателя.
- `console-licensing-ui`: консольный раздел «Лицензирование» — вкладки организаций, планов и лицензий, сервисный/правовой гейт раздела, тексты `console.*`.

### Modified Capabilities

- `console-service-management`: список переключаемых сервисов экрана «Сервисы проекта» пополняется лицензированием (контент, аналитика, оплата, лицензирование).

## Impact

- **Код**: `packages/cms/auth` (enum `ServiceName`, конфиг `cms-auth.php`, `CreateProjectHandler` — сервисы по умолчанию, бэкфилл-миграция), `packages/cms/licensing` (манифест + команда публикации, middleware в `routes/admin.php`), фронтенд: `frontends/admin` и `frontends/source-admin` (страница раздела, `sidebar-config.ts`, `section-access.ts`, `ServicesSection`, `console-texts.ts`, hooks), `frontends/admin/src/lib/admin/data-source/platform/licensing.ts` и services-фасад (только admin-дерево).
- **БД auth-service**: новые строки `project_services` (`licensing`, enabled) — бэкфилл существующих проектов и автосоздание при создании проекта. Схема таблиц не меняется.
- **API**: новых эндпоинтов нет; у licensing-маршрутов меняется только middleware сервисного гейта (обновить снимки `RouteCoverageTest`/характеризационные, если фиксируют middleware). Swagger не меняется — пути и схемы прежние.
- **Инструменты/тесты**: e2e `console-navigation.spec.ts`, `section-access.test.ts`, `console-texts.test.ts`; публикация манифеста лицензирования там же, где публикуются остальные манифесты (стек/смоук); пересборка admin-front при проверке.
- **Не затрагивается**: gateway (Caddyfile, префиксы URL), схема и данные pay-service, имена прав, контракты admin/public API лицензирования, публичный эндпоинт валидации.
