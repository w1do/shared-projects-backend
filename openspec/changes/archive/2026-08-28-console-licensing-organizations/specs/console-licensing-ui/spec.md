# console-licensing-ui Specification (delta)

## Purpose

Консольный раздел «Лицензирование»: управление организациями-покупателями, планами поставки с фичами и лицензионными ключами проекта из панели — без обращения к API вручную.

## ADDED Requirements

### Requirement: Раздел «Лицензирование» в панели

Панель SHALL предоставлять раздел «Лицензирование», объявленный за сервисом `licensing` и правом `pay.licensing.view`: пункт меню SHALL отображаться только при включённом сервисе и наличии права, прямой переход по адресу без доступа SHALL вести на страницу отказа. Раздел SHALL содержать вкладки организаций, планов и лицензий. Экраны SHALL собираться из существующих компонентов вёрстки без изменения дизайн-системы; тексты SHALL определяться ключами `console.*` с русскими значениями по умолчанию.

#### Scenario: Раздел виден при включённом сервисе и праве

- **WHEN** сервис `licensing` включён для проекта и у оператора есть право `pay.licensing.view`
- **THEN** пункт «Лицензирование» присутствует в меню и раздел открывается

#### Scenario: Выключение сервиса скрывает раздел сразу

- **WHEN** администратор выключает сервис `licensing` на экране управления сервисами
- **THEN** пункт «Лицензирование» исчезает из меню без повторного входа, а прямой адрес раздела ведёт на страницу отказа

#### Scenario: Тексты на русском по умолчанию

- **WHEN** оператор с локалью по умолчанию открывает раздел
- **THEN** заголовки, вкладки, колонки таблиц, кнопки, пустые состояния и сообщения отображаются на русском из реестра `console.*`

### Requirement: Управление организациями

Вкладка организаций SHALL показывать организации текущего проекта списком с пагинацией и позволять оператору с правом `pay.licensing.manage` создавать, изменять и удалять анкету организации (название, контактное лицо, телефон, e-mail, telegram, сфера деятельности, число сотрудников, цель использования). Ошибки валидации и доменные ошибки SHALL показываться оператору понятным сообщением, список SHALL отражать фактически сохранённое состояние.

#### Scenario: Создание организации

- **WHEN** оператор с правом manage создаёт организацию, указав название, контактное лицо и e-mail
- **THEN** организация появляется в списке, оператор видит подтверждение

#### Scenario: Удаление организации с лицензиями отклоняется

- **WHEN** оператор удаляет организацию, у которой есть лицензия
- **THEN** показывается сообщение доменной ошибки, организация остаётся в списке

### Requirement: Управление планами и фичами

Вкладка планов SHALL показывать планы поставки проекта и позволять оператору с правом `pay.licensing.manage` создавать, изменять и удалять план (code, название, опциональная цена периода: сумма, валюта, интервал — заполняются только все три вместе), управлять базовыми фичами плана и пер-организационными переопределениями. Просмотр плана SHALL показывать его базовые фичи и переопределения по организациям.

#### Scenario: План с частично заполненной ценой отклоняется

- **WHEN** оператор сохраняет план с заполненной суммой, но без валюты или интервала
- **THEN** форма показывает ошибку валидации, план не сохраняется

#### Scenario: Переопределение фичи для организации

- **WHEN** оператор добавляет плану фичу для конкретной организации
- **THEN** в просмотре плана фича видна как переопределение этой организации, базовые фичи не изменяются

### Requirement: Управление лицензиями

Вкладка лицензий SHALL показывать лицензии проекта (организация, план, активационный ключ, даты выпуска и истечения, вычисленный статус) с фильтрами по организации и статусу и позволять оператору с правом `pay.licensing.manage`: выпустить лицензию (организация + план + срок действия), отозвать лицензию с подтверждением, скачать лицензионный файл, просмотреть публичный ключ подписи проекта. Доменные ошибки (например, повторный отзыв) SHALL показываться сообщением.

#### Scenario: Выпуск лицензии

- **WHEN** оператор с правом manage выпускает лицензию, выбрав организацию, план и срок действия в будущем
- **THEN** лицензия появляется в списке со статусом `active`, её лицензионный файл доступен для скачивания

#### Scenario: Отзыв лицензии

- **WHEN** оператор отзывает активную лицензию, подтвердив действие
- **THEN** лицензия отображается со статусом `revoked`

#### Scenario: Фильтр по статусу

- **WHEN** оператор применяет фильтр по статусу `expired`
- **THEN** в списке только лицензии с истёкшим сроком действия

### Requirement: Режим «только чтение» без права manage

Оператору с правом `pay.licensing.view` без `pay.licensing.manage` раздел SHALL быть доступен только на чтение: создание, изменение, удаление, выпуск, отзыв, скачивание лицензионного файла и просмотр ключа подписи SHALL быть недоступны в интерфейсе.

#### Scenario: Оператор без права manage

- **WHEN** раздел открывает оператор только с правом `pay.licensing.view`
- **THEN** списки организаций, планов и лицензий видны, изменяющие действия недоступны
