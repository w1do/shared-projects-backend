# licensing/service-registration Specification (delta)

## Purpose

Лицензирование как самостоятельный переключаемый сервис платформы: регистрация в реестре сервисов, манифест с навигацией консоли, сервисный гейт admin-маршрутов модуля и включённость по умолчанию во всех проектах.

## ADDED Requirements

### Requirement: Сервис licensing в реестре платформы

Платформа SHALL включать `licensing` в реестр переключаемых сервисов: сервис SHALL включаться и выключаться на проект штатным API управления сервисами наравне с остальными. Лицензирование SHALL иметь собственный манифест сервиса (ключ `licensing`) с навигацией консольного раздела, публикуемый в auth-service вместе с манифестами остальных сервисов; bootstrap консоли SHALL отдавать навигацию лицензирования только при включённом сервисе. Права модуля SHALL сохранять существующие имена `pay.licensing.view` и `pay.licensing.manage` — переименований и перенастройки ролей MUST NOT требоваться.

#### Scenario: Переключение сервиса штатным API

- **WHEN** администратор выключает сервис `licensing` через API управления сервисами и консоль перечитывает bootstrap
- **THEN** состояние сохранено, навигация лицензирования не отдаётся; после включения — отдаётся снова

#### Scenario: Имена прав не меняются

- **WHEN** оператору назначена роль с правом `pay.licensing.view`, выданным до этого изменения
- **THEN** право продолжает открывать просмотр лицензирования без перенастройки ролей

### Requirement: Гейт admin-маршрутов по собственному сервису

Admin-маршруты модуля лицензирования SHALL быть закрыты гейтом сервиса `licensing`: для проекта с выключенным сервисом они SHALL возвращать 404, данные при этом MUST NOT удаляться. Гейт SHALL быть независим от сервиса `pay`: выключение `pay` MUST NOT выключать лицензирование, выключение `licensing` MUST NOT влиять на платёжные маршруты.

#### Scenario: Выключенный сервис — 404

- **WHEN** оператор обращается к admin-маршруту лицензирования в проекте с выключенным сервисом `licensing`
- **THEN** ответ — 404; после включения сервиса данные доступны в прежнем виде

#### Scenario: Независимость от pay

- **WHEN** сервис `pay` выключен, а `licensing` включён
- **THEN** admin-маршруты лицензирования работают, платёжные маршруты возвращают 404

### Requirement: Включённость по умолчанию во всех проектах

Сервис `licensing` SHALL быть включён по умолчанию: при создании проекта он SHALL включаться автоматически без действий администратора; при внедрении изменения он SHALL оказаться включённым во всех существующих проектах. Администратор SHALL мочь выключить его штатным переключателем, и явное выключение SHALL сохраняться — авто-включение MUST NOT перезаписывать его.

#### Scenario: Новый проект

- **WHEN** создаётся новый проект
- **THEN** сервис `licensing` включён в нём без дополнительных действий

#### Scenario: Существующие проекты после внедрения

- **WHEN** изменение внедрено на площадке с существующими проектами
- **THEN** сервис `licensing` включён во всех существующих проектах

#### Scenario: Явное выключение сохраняется

- **WHEN** администратор выключил сервис `licensing` в проекте
- **THEN** сервис остаётся выключенным до явного включения

### Requirement: Публичная валидация вне переключателя

Публичный эндпоинт онлайн-валидации лицензионных ключей SHALL оставаться доступным независимо от состояния переключателя сервиса `licensing`: выключение сервиса MUST NOT нарушать проверку уже выданных лицензий в self-hosted-поставках.

#### Scenario: Валидация при выключенном сервисе

- **WHEN** сервис `licensing` выключен для проекта, а поставка отправляет активационный ключ активной лицензии этого проекта
- **THEN** ответ валидации обычный: статус `active`, code плана, коды фич, `expires_at`
