# Proposal: console-service-sync

## Why

Панель показывает все 16 разделов исходной вёрстки независимо от того, что умеет платформа и что разрешено оператору: каталог товаров, заказы, промо, кампании, поддержка и уведомления живут на демо-данных, потому что соответствующих сервисов в платформе нет. Оператор не отличает рабочий раздел от витринного, а разделы выключенного или недоступного по правам сервиса всё равно висят в меню.

При этом платформа уже отдаёт всё нужное одним запросом: `GET /api/admin/v1/bootstrap` возвращает включённые для проекта сервисы, их навигацию из манифестов (`key`, `label`, `route`, `permission`, `order`) и список прав оператора. Нужно собрать меню и доступ к разделам из этих данных, а лишнее скрыть — не удаляя ни вёрстку, ни код разделов.

## What Changes

- **Меню строится из bootstrap**: состав и порядок разделов определяются включёнными сервисами проекта и правами оператора, а не статическим списком. Раздел показывается, только если его сервис включён и у оператора есть право из манифеста.
- **Разделы без сервиса платформы скрываются**: каталог (`products`, `variants`, `brands`, `collections`, `inventory`), `orders`, `campaigns`, `promotions`, `support`, `notifications` пропадают из меню и быстрых действий. Их страницы, компоненты, демо-данные и маршруты **остаются в репозитории нетронутыми** — они просто не показываются.
- **Прямой переход на скрытый раздел** уводит на существующую страницу отказа `/admin/unauthorized`; новых экранов не добавляется.
- **Снимок доступа сохраняется при входе** и обновляется при смене проекта/перезаходе, чтобы серверный guard (`src/proxy.ts`) мог решать по cookie, а меню — рендериться без ожидания запроса.
- **Быстрые действия** (`quickActions`) фильтруются тем же правилом, чтобы не вести на скрытые разделы.
- **Не входит**: удаление разделов, страниц или демо-данных; новые экраны и пункты меню; изменение дизайна и текстов; правки backend-манифестов и API.

## Capabilities

### New Capabilities

- `console-navigation`: состав разделов панели и доступ к ним определяются включёнными сервисами проекта и правами оператора из `bootstrap`; разделы без поддержки платформы скрыты, но сохранены.

### Modified Capabilities

нет (`admin-console` ещё не архивирован; его требования не меняются — добавляется отдельная способность видимости разделов).

## Impact

- `frontends/admin/src/lib/admin/sidebar-config.ts` — каждому пункту добавляется ключ раздела; состав меню начинает вычисляться.
- Новый модуль доступа в `src/lib/admin/data-source/` — снимок bootstrap (сервисы + права) и селектор видимых разделов.
- `frontends/admin/src/proxy.ts` — guard для скрытых разделов → `/admin/unauthorized`.
- `frontends/admin/src/components/layout/AdminSidebar.tsx` — минимальная правка: рендер из вычисленного списка вместо статического (зеркалится в `frontends/source-admin`, как уже сделано для `LoginForm.tsx`, чтобы CI-diff вёрстки оставался зелёным).
- `docs/admin-console.md` и README — таблица разделов дополняется правилом видимости.
- Появляются e2e-сценарии панели (Playwright): состав меню, отказ по прямому адресу и сквозной прогон через gateway. Harness для их запуска вводится отдельным изменением.
- Backend не затрагивается: используются существующие `bootstrap`, манифесты и права.
