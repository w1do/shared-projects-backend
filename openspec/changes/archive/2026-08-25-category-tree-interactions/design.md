# Design: category-tree-interactions

## Context

См. `proposal.md`. Требования — `specs/category-tree-dnd/spec.md`, `specs/category-tree-select/spec.md`.

Ограничения, определяющие решения:

- **Новые npm-зависимости панели невозможны**: `frontends/admin` живёт на Bun, CI ставит с `--frozen-lockfile`, bun на машине разработки отсутствует — `bun.lock` пересчитать нечем. dnd-kit и подобные исключены; в наличии `framer-motion` и нативные drag-события браузера.
- Дизайн-система — компоненты вёрстки в `src/components/ui/`: `table.tsx`, `data-grid.tsx`, `command.tsx` (cmdk, поиск), `popover`, `checkbox`, `badge`. CI сверяет `src/components` с `frontends/source-admin` — всё новое зеркалится.
- Слой дерева уже есть: `category-tree.ts` (плоский префиксный список, `depth`, `invalidParentIds`) с юнит-тестами; `moveCategory` в сервисном слое; мутация с инвалидацией.
- **`MoveCategoryHandler` игнорирует `position`**: поле объявлено в `MoveCategoryDTO` и валидируется, но handler обрабатывает только `parent_id` — `appendToNode` всегда ставит узел в конец. Порядок соседей задать нельзя, пока это не дореализовано.
- Playwright-harness готов; для DnD пригодны `page.dragTo` / ручные `mouse.down/move/up`.

## Goals / Non-Goals

**Goals:**

- Перетаскивание — основной жест управления деревом; формы остаются как доступная альтернатива.
- Оба компонента — переиспользуемые части дизайн-системы, не одноразовые куски экрана категорий.
- Целостность дерева гарантирует платформа (nested set); панель лишь не предлагает заведомо недопустимого.

**Non-Goals:**

- Перетаскивание между страницами пагинации: дерево показывается целиком (см. решение 5).
- Множественное перетаскивание, перетаскивание в другие разделы.
- Виртуализация списка: деревья категорий — десятки узлов, не тысячи.

## Decisions

### 1. DnD — нативные drag-события, без библиотек

`TreeTable` использует `draggable` + `onDragStart/Over/Leave/Drop` строк. Причина безальтернативна: зависимость добавить нельзя (лок панели пересчитать нечем). Нативного API достаточно: перетаскиваются целые строки, произвольного позиционирования и анимаций перetaskивания не требуется; ghost-изображение даёт браузер.

Зоны броска на строке: **верхняя треть** — вставить перед строкой (сосед), **нижняя треть** — после, **середина** — вложить в строку. Текущая зона подсвечивается: линия-вставка сверху/снизу либо подсветка всей строки для вложения. Это стандартная семантика деревьев (файловые менеджеры), различимая без подписи.

### 2. `TreeTable` — компонент дизайн-системы, данные снаружи

Живёт в `src/components/ui/data-display/tree-table.tsx`, строится на примитивах `table.tsx`. Принимает плоский список узлов (`id`, `parentId`, `depth` — форма, которую уже отдаёт `category-tree.ts`), колонки в духе `data-grid.types.ts` и колбэк `onMove(nodeId, parentId, position)`. Сам не знает ни о категориях, ни об API: правила недопустимых целей приходят предикатом. Экран категорий поставляет данные и мутацию.

Альтернатива — вшить DnD прямо в экран категорий — отвергнута: просьба явная «таблица для tree node на основе дизайн-системы», и компонент понадобится любому будущему дереву (внешние проекты, страницы).

### 3. Сворачивание ветвей — состояние компонента, набор скрытых строк

Свёрнутость — `Set<string>` свёрнутых узлов в состоянии `TreeTable`; скрытые строки не рендерятся, но остаются в данных. Свёрнутый узел — допустимая цель вложения. Состояние живёт в пределах экрана (не в URL и не в хранилище): требование — «в пределах сеанса работы с разделом».

### 4. Порядок соседей: дореализовать `position` в `MoveCategoryHandler`

Handler дополняется: при заданном `position` узел после смены родителя вставляется в позицию среди соседей (`insertBeforeNode`/`insertAfterNode` nested set), при отсутствующем — в конец, как сейчас. Существующие вызовы без `position` не меняют поведения — правка аддитивна. Покрывается Pest-тестом на порядок после перемещения.

Альтернатива — хранить порядок на панели — отвергнута: порядок уровня уже хранится платформой в lft/rgt, второй источник истины разъедется с первым.

### 5. Экран категорий показывает дерево целиком, пагинация уходит

Перетаскивание между страницами невозможно по построению, а дерево, разрезанное на страницы, бессмысленно (потомок на другой странице, чем родитель). Список категорий проекта — десятки узлов; `TreeTable` рендерит все строки, пагинация на экране категорий снимается (в mock-режиме плоского каталога остаётся прежний экран — см. решение 7). Поиск остаётся: он фильтрует строки, DnD при активном поиске отключается (порядок отфильтрованного списка не отражает соседства).

### 6. `CategoryTreeSelect` — Popover + Command, два режима

`src/components/ui/inputs/category-tree-select.tsx`: триггер-кнопка в стиле `Select` вёрстки, внутри `Popover` с `Command` — поиск уже реализован в cmdk. Узлы — `CommandItem` с отступом по `depth`; при активном поиске у найденного узла показывается цепочка предков («Аналитика / Рынок»). Режимы: `single` (значение — id или null-корень, опция «No parent (root)» включаема пропсом) и `multiple` (чекбоксы в строках, счётчик и имена в триггере). Недопустимые узлы передаются `Set`-ом и рендерятся `disabled`.

Применение: форма поста (multiple, вместо блока чекбоксов), формы категории и диалог перемещения (single, вместо `Select` с плоскими отступами). `parent-options.ts` упраздняется в пользу прямой передачи дерева и `invalidParentIds`.

### 7. Mock-режим не трогается

В mock-режиме категории — плоский каталог вёрстки без дерева. Экран категорий использует `TreeTable` только когда данные несут `depth` (режим api), иначе рендерит прежнюю таблицу; форма поста в mock-режиме сохраняет прежний блок. Это то же ветвление, что уже сделано для фильтра статусов блогов.

### 8. Оптимистичного обновления нет — перечитывание после `move`

Как и в диалоге перемещения: локальный пересчёт дерева повторял бы логику nested set на клиенте. После броска строка помечается «в полёте» (приглушение), по успеху дерево перечитывается, по ошибке — тост с текстом платформы и возврат прежнего вида. Задержка одного запроса на десятках узлов незаметна.

## Risks / Trade-offs

- [Нативный HTML5 DnD не работает с тачскрина] → на сенсорных устройствах остаются формы и диалог «Move to…» (требование «доступно без перетаскивания»); отдельная поддержка тача — вне объёма.
- [Playwright и нативный DnD капризны (dragTo не всегда триггерит dragover)] → сценарии используют ручную последовательность `mouse.down → move (несколько шагов) → up`; если событийная модель окажется нестабильной, сценарий опускается до проверки вызова `onMove` с правильными аргументами + API-проверки результата.
- [Правка бекенда в изменении, которое казалось фронтовым] → изменение маленькое и аддитивное (обработка уже объявленного поля DTO), покрыто Pest-тестом; без него требование порядка невыполнимо — честнее включить, чем молча сузить.
- [Снятие пагинации на экране категорий меняет вёрстку экрана] → зеркалится в `source-admin`; mock-режим сохраняет прежний вид, CI-diff остаётся зелёным.
- [Три места выбора родителя переходят на новый компонент разом] → за каждым местом остаётся прежний обработчик сохранения; сценарии `console-content-management` продолжают проходить и служат регрессионной сеткой.

## Migration Plan

Панель: новые компоненты аддитивны, экраны переключаются по одному; откат — вернуть прежние блоки (они не удаляются до конца изменения). Бекенд: обработка `position` аддитивна, вызовы без него не меняются; откат — убрать ветку. После завершения прежний `parent-options.ts` и блок чекбоксов удаляются.

## Open Questions
