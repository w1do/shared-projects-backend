## Purpose

Определяет базу знаний проекта: всё, что добыто исследованиями, накапливается в векторном хранилище с обязательным набором метаданных и доступно для смыслового поиска, чтобы последующая генерация опиралась на собранный материал, а не на память модели.

## ADDED Requirements

### Requirement: Каждый завершённый проход исследования попадает в базу знаний

Каждое успешно завершённое исследование SHALL записываться в базу знаний проекта. Запись MUST происходить после завершения сбора и MUST NOT требовать отдельного действия оператора. Неуспешное или отменённое исследование MUST NOT записываться.

#### Scenario: Успешный проход сохраняется

- **WHEN** исследование завершилось успешно
- **THEN** его материал появляется в базе знаний проекта без действий оператора

#### Scenario: Неуспешный проход не сохраняется

- **WHEN** исследование завершилось ошибкой или было отменено
- **THEN** в базу знаний ничего не записывается

### Requirement: Обязательные метаданные записи

Каждая запись базы знаний SHALL содержать метаданные: тему, исходный запрос, содержимое, дату и категорию. Запись без любого из этих полей MUST NOT сохраняться. Дополнительно запись SHOULD хранить ссылку на источник и идентификатор исследования, из которого получена.

#### Scenario: Полный набор метаданных

- **WHEN** материал исследования записывается в базу знаний
- **THEN** у записи заполнены тема, запрос, содержимое, дата и категория

#### Scenario: Неполные метаданные

- **WHEN** для материала не удалось определить обязательное поле метаданных
- **THEN** запись не сохраняется, а причина попадает в журнал

### Requirement: Смысловой поиск по базе знаний

Платформа SHALL поддерживать поиск по базе знаний проекта по смыслу запроса, а не только по совпадению слов. Результат SHALL содержать найденные записи с их метаданными и мерой близости, отсортированные от наиболее близких. Поиск SHALL поддерживать отбор по категории и по диапазону дат.

#### Scenario: Поиск по смыслу

- **WHEN** выполняется поиск по формулировке, дословно не встречающейся в материале
- **THEN** возвращаются близкие по смыслу записи с их метаданными

#### Scenario: Отбор по категории

- **WHEN** поиск ограничен категорией
- **THEN** в результат попадают только записи этой категории

#### Scenario: Ничего не найдено

- **WHEN** в базе знаний проекта нет близких записей
- **THEN** возвращается пустой результат, а не ошибка

### Requirement: Изоляция базы знаний по проекту

База знаний SHALL быть изолирована по проекту: поиск и чтение MUST возвращать только записи текущего проекта. Материал одного проекта MUST NOT попадать в выдачу другого ни при каком запросе.

#### Scenario: Поиск не пересекает проекты

- **WHEN** в двух проектах накоплен материал по одной теме и выполняется поиск в первом
- **THEN** возвращаются только записи первого проекта

### Requirement: Недоступность хранилища не рушит исследование

Отказ или недоступность хранилища базы знаний MUST NOT отменять результат исследования: собранный материал SHALL сохраняться в платформе, а запись в базу знаний SHALL повторяться. Повторная запись того же прохода MUST NOT создавать дубликат.

#### Scenario: Хранилище недоступно при записи

- **WHEN** база знаний недоступна в момент записи завершённого исследования
- **THEN** результат исследования остаётся доступен оператору, а запись повторяется позже

#### Scenario: Повторная запись прохода

- **WHEN** запись одного и того же прохода исследования выполняется повторно
- **THEN** в базе знаний не появляется дубликат
