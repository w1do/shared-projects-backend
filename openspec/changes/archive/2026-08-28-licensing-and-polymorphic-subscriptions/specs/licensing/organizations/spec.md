# licensing/organizations Specification (delta)

## Purpose

Реестр организаций-покупателей self-hosted-поставок: анкета организации (контакты, сфера деятельности, размер, цель использования) и admin API управления ею как основа для выпуска лицензий.

## ADDED Requirements

### Requirement: Модель организации-покупателя

Система SHALL хранить анкету организации-покупателя с атрибутами: `name` (название организации), `contact_first_name` и `contact_last_name` (имя и фамилия контактного лица), `phone`, `email`, `telegram`, `activity` (чем занимается организация), `employees_count` (число сотрудников, целое неотрицательное), `usage_purpose` (цель использования), `project_id`. Обязательными SHALL быть `name`, `contact_first_name`, `contact_last_name`, `email`; остальные поля анкеты опциональны. Каждая организация SHALL принадлежать ровно одному проекту.

#### Scenario: Создание организации с полной анкетой

- **WHEN** оператор создаёт организацию, передав название, контактное лицо, телефон, e-mail, telegram, сферу деятельности, число сотрудников и цель использования
- **THEN** организация сохраняется в текущем проекте со всеми переданными полями анкеты

#### Scenario: Анкета без обязательных полей отклоняется

- **WHEN** оператор создаёт организацию без названия или без e-mail
- **THEN** система возвращает ошибку валидации в стандартном envelope, организация не создаётся

### Requirement: Admin CRUD организаций

Система SHALL предоставлять admin-эндпоинты списка и просмотра организаций проекта под правом `pay.licensing.view`, а создания, изменения и удаления — под правом `pay.licensing.manage`. Список SHALL поддерживать пагинацию и возвращать только организации текущего проекта.

#### Scenario: Список организаций своего проекта

- **WHEN** оператор с правом `pay.licensing.view` запрашивает список организаций
- **THEN** ответ содержит только организации текущего проекта; организации других проектов недоступны ни в списке, ни по прямому идентификатору

#### Scenario: Изменение анкеты под правом manage

- **WHEN** оператор с правом `pay.licensing.manage` обновляет телефон и число сотрудников организации
- **THEN** анкета обновляется, остальные поля не изменяются

#### Scenario: Нет права — нет доступа

- **WHEN** оператор без права `pay.licensing.view` запрашивает список организаций
- **THEN** система возвращает ошибку доступа в стандартном envelope

### Requirement: Защита организации с лицензиями от удаления

Система SHALL запрещать удаление организации, у которой существует хотя бы одна лицензия (в любом статусе), возвращая доменную ошибку валидации.

#### Scenario: Удаление организации с лицензией отклоняется

- **WHEN** оператор с правом `pay.licensing.manage` удаляет организацию, для которой выпущена лицензия
- **THEN** система возвращает доменную ошибку валидации, организация и её лицензии сохраняются

#### Scenario: Удаление организации без лицензий

- **WHEN** оператор с правом `pay.licensing.manage` удаляет организацию без лицензий
- **THEN** организация удаляется вместе с её переопределениями фич
