# Proposal: licensing-and-polymorphic-subscriptions

## Why

Часть сайтов платформы распространяется как self-hosted/opensource-поставка, и сейчас нет способа контролировать коммерческое использование: кому продана копия, какой тариф, какие фичи доступны и до какого срока. Нужен модуль лицензирования: реестр организаций-покупателей, планы поставки с фичами и подписанные лицензионные ключи в духе GitLab.

Одновременно подписки `cms/pay` привязаны к подписчику строкой `user_key` и к предмету жёстким FK `plan_id` — новая сущность-подписчик (организация) и новый предмет подписки (лицензионный план) в эту модель не помещаются, а в будущем появятся и другие. Поэтому подписки переводятся на полиморфную модель уже на этом этапе: подписчик и предмет — расширяемые полиморфные пары, лицензирование становится первым потребителем.

## What Changes

### Полиморфные подписки (рефакторинг `cms/pay`)

- **BREAKING** Схема `subscriptions`: строка `user_key` заменяется парой `subscriber_type`+`subscriber_id` (пользователь сайта — «внешний» тип без локальной таблицы, организация — локальная модель licensing), жёсткий FK `plan_id` — парой `subject_type`+`subject_id`; данные бэкфиллятся из текущих `user_key`/`plan_id`.
- Контракт предмета подписки `Subscribable` (цена периода, интервал, код) в `cms/shared`; тарифный план `cms/pay` реализует его; renewal-цикл (оформление, продление, продление периода по оплате) работает через контракт, а не через `plan`-relation.
- **BREAKING** Wire-форма ответов: в `SubscriptionResource` вместо `user_key` — объект `subscriber {type, id}`, предмет — полиморфный ресурс; в `PaymentResource`/таблице `payments` `user_key` переименовывается в `subject_key` (денормализованный аналитический ключ плательщика). Контракт публичного оформления сайта (`plan_code` + `X-User-Token`) сохраняется без изменений.
- Субъект-ключ аналитики для site-пользователей сохраняет прежний формат `user:{project}:{id}` (непрерывность истории ClickHouse и склейка с событиями auth); для организаций вводится `organization:{project}:{id}`; `Cms\Shared\Analytics` учится выводить `project_id` из обобщённого формата `{type}:{project}:{id}`.
- Межмодульные события подписки в `cms/contracts`: `SubscriptionStarted` и `SubscriptionPeriodExtended` (скалярные payload) — раньше событий подписки не существовало вовсе.
- Admin-эндпоинт оформления подписки (подписчик+предмет), право `pay.subscriptions.manage` — раньше админ мог только менять существующие.
- Попутный багфикс: повторное неуспешное продление `past_due`-подписки больше не роняет ретрай-цикл (переход `past_due → past_due`), как и требовала действующая спека.
- Переснятие снимков-контрактов (19 снимков с литералом `user_key`), обновление smoke-сценария при необходимости, пересборка swagger.

### Модуль лицензирования (новый пакет `packages/cms/licensing`)

- Новый модуль-пакет `packages/cms/licensing` (namespace `Cms\Licensing`, канонический four-layer) в `apps/pay-service`.
- **Organization** — анкета организации-покупателя (название, контактное лицо, телефон, e-mail, telegram, сфера деятельности, число сотрудников, цель использования); admin CRUD; организация — полноправный полиморфный подписчик.
- **Plan** и **PlanFeature** лицензионной поставки (таблицы `license_*`, отдельные от подписочных): план — тариф поставки с опциональной ценой периода (реализует `Subscribable`, когда цена задана), фичи — именованные возможности с пер-организационными переопределениями (nullable `organization_id`).
- **License** — лицензионный ключ организации: активационный ключ, подписанный Ed25519 payload (лицензионный файл), `expires_at`, отзыв; пер-проектная ключевая пара, публичный ключ встраивается в поставку, офлайн-проверка + публичный эндпоинт онлайн-валидации.
- **Интеграция с подписками**: оформление подписки организации на лицензионный план автоматически выпускает лицензию со сроком до конца оплаченного периода; успешная оплата продления перевыпускает лицензию с новым `expires_at` (активационный ключ сохраняется); отмена подписки лицензии не отзывает — она доживает до `expires_at`.
- Admin API под правами `pay.licensing.view|manage`; миграции, Swagger, Pest-тесты, регистрация пакета в ArchitectureGateTest и `refactor-inventory --strict`.

## Capabilities

### New Capabilities

- `licensing/organizations`: реестр организаций-покупателей — модель анкеты, admin CRUD, tenant-изоляция по `project_id`.
- `licensing/plans`: планы лицензионной поставки и их фичи — модель Plan/PlanFeature, опциональная цена периода, пер-организационные переопределения фич, admin CRUD.
- `licensing/license-keys`: выпуск, подпись, отзыв и валидация лицензионных ключей — Ed25519-пара проекта, формат лицензионного файла, активационный ключ, публичная валидация.
- `licensing/license-subscriptions`: жизненный цикл лицензии, управляемый подпиской организации на лицензионный план — авто-выпуск, продление по оплате, поведение при отмене.

### Modified Capabilities

- `pay-service`: требование «Подписки» — подписчик и предмет становятся полиморфными парами, admin-оформление, уникальность живой подписки на пару подписчик+предмет; требование «События платежей в аналитику» — «ключ пользователя» обобщается до субъект-ключа подписчика.
- `payments/payment-analytics`: «Событие инициализации платежа» и «Полная история платежей по пользователю» — субъект события обобщается с пользователя до подписчика (subject key), история склеивается по субъекту любого типа.

## Impact

- **Код**: рефакторинг подписочного конвейера `cms/pay` (модель, VO `SiteUserKey` → `Subscriber`, policy, handlers, queries, listeners, DTO, resources); `cms/shared` (`Subscribable`, парсер subject-ключей Analytics, `RequestIntrospection`); `cms/contracts` (события подписки); новый пакет `packages/cms/licensing`; `PayManifest` (+права `pay.licensing.*`).
- **БД pay-service**: ALTER `subscriptions` (морф-колонки, бэкфилл, drop FK) и `payments` (rename `user_key`→`subject_key`); новые таблицы `licensing_organizations`, `license_plans`, `license_plan_features`, `licenses`, `license_signing_keys`.
- **API**: **BREAKING** форма ответов подписок/платежей (см. выше); новые admin-маршруты `/api/admin/v1/projects/{project}/pay/licensing/*`, admin-оформление подписки, публичный `/api/v1/pay/licensing/validate` (под существующими pay-префиксами gateway — Caddyfile не меняется); swagger пересобирается `./tools/cms api` (иначе упадут OpenApiContractTest всех четырёх сервисов).
- **Аналитика**: формат subject-ключа site-пользователей не меняется (история непрерывна); новые субъекты `organization:*`; события подписок и платежей организаций попадают в общую хронологию по своему субъекту.
- **Тесты**: переснятие 19 снимков-контрактов с `user_key`, правка фикстур в 9 тест-файлах (фабрик Subscription/Payment нет — сырые `Model::create`), характеризационные снимки и записи RouteCoverageTest для новых licensing-маршрутов, `tools/smoke.sh` остаётся зелёным (не читает `user_key`).
- **Зависимости**: только ext-sodium (входит в PHP 8.3) — новых composer-пакетов не требуется.
- **Не затрагивается**: консольный фронтенд (экранов подписок в нём нет, из pay-API использует только настройки провайдеров), gateway-маршрутизация (URL-префиксы не меняются), каталог планов и платёжные шлюзы.
