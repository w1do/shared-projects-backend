# Proposal: admin-console

## Why

Готовая вёрстка админки лежит в `frontends/source-admin` (Next.js 16 + React 19 + Tailwind v4, запуск на Bun, 16 разделов, дизайн-система). Текущее содержимое `frontends/admin` — неудачная попытка перенести её на Vite с shim'ами `next/*`: белый экран, зависания, `process is not defined`, отсебятина в точке входа. Владелец требует: перенести вёрстку **как есть**, ничего от себя не добавлять, запускать на Bun в том же виде, а сверху подключить API платформы и реальный вход с попаданием на главный дашборд.

Вёрстка изначально спроектирована под подключение бекенда: слой `src/lib/admin/data-source/` уже имеет режимы `mock | api`, свой api-client, типы и мапперы. Значит интеграция делается **в слое данных вёрстки, без правок компонентов и разметки**.

## What Changes

- **`frontends/admin` очищается полностью** и заполняется побайтовой копией `frontends/source-admin` (src, public, next.config.ts, tsconfig, конфиги eslint/prettier/postcss, package.json, bun.lock). Никаких Vite, shim'ов `next/*`, самописных роутеров и точек входа — ничего этого больше нет.
- **Запуск на Bun** в том же виде, что у исходника: `bun install`, `bun run dev` / `bun run build` + `bun run start`. Контейнер `admin-front` переезжает с node/Vite на образ Bun; gateway продолжает отдавать панель на `/` (Next сам редиректит `/` → `/admin`).
- **Реальный вход оператора**: аутентификация против auth-service (`POST /api/admin/v1/auth/login`, guard `admin`), сессия хранится так, как этого ждёт вёрстка (cookie `auth_token` + `current_user`), после успеха — редирект на `/admin` (главный дашборд). Форма логина и её разметка не меняются: подменяется только реализация модуля аутентификации в слое данных.
- **Защита разделов**: доступ к `/admin/**` без валидной сессии уводит на `/login`; выход чистит сессию и токен.
- **API-интеграция через встроенный режим `api`**: `NEXT_PUBLIC_ADMIN_DATA_SOURCE=api` включает уже существующий путь данных вёрстки; расхождения контрактов (конверт ответа, пагинация, формат логина, поля сущностей) закрываются в `src/lib/admin/data-source/*` — api-client, мапперы и запросы, — то есть в слое данных, а не в компонентах.
- **Разделы, которым есть соответствие в платформе, получают живые данные** (посты/страницы/категории/SEO → content-service, тарифы/платежи/подписки → pay-service, отчёты и история → analytics-service, проекты/участники/роли/ключи → auth-service). Разделы без бекенд-аналога (например витринные разделы вроде brands/collections/promotions) остаются на mock-данных вёрстки в неизменном виде.
- **Не входит**: изменение дизайна, вёрстки, состава разделов и текстов; новые экраны; правки backend-API ради удобства фронта (кроме уже существующих эндпоинтов).

## Capabilities

### New Capabilities

- `admin-console`: панель управления платформой — перенесённая вёрстка на Bun/Next.js, вход оператора, защита разделов, подключение разделов к API платформы через встроенный слой данных.

### Modified Capabilities

нет.

## Impact

- Полная замена содержимого `frontends/admin`; удаление Vite-конфигурации, shim'ов `next/*` и самописного `main.tsx`.
- `infra/compose/compose.yaml`: сервис `admin-front` на Bun-образе; env вёрстки (`NEXT_PUBLIC_ADMIN_*`) в `infra/services/admin-front/.env`.
- `infra/gateway/Caddyfile`: правила для Next (статика `/_next/*`, страницы, редирект `/` → `/admin`).
- CI: сборка админки через Bun вместо npm-workspace-сборки.
- Пакеты `packages/frontend/*` (ui-kit/api-client) остаются как есть и в этом change не используются панелью: источник дизайна и данных — сама вёрстка.
