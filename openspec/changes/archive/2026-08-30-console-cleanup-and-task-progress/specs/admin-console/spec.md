## MODIFIED Requirements

### Requirement: Вёрстка берётся из склада `source-admin`

`frontends/source-admin` SHALL быть складом готовой вёрстки: эталон, из которого консоль берёт нужные части. Он не запускается как приложение и не развивается. `frontends/admin` SHALL содержать только то, что уже подключено к платформе.

Раздел консоли SHALL собираться переносом частей склада в `admin` и подключением их к API платформы. Разметка, стили и дизайн-система перенесённых частей MUST NOT переделываться. Файл, присутствующий и в складе, и в консоли, SHALL совпадать побайтово; изменение перенесённого файла SHALL переноситься обратно в склад тем же изменением. Собственные компоненты консоли, которых в складе нет, живут только в `admin`.

Тексты видимых разделов в `frontends/admin` SHALL быть локализованы (русский — язык по умолчанию) через реестр `console.*`. Слой представления MUST NOT содержать самописных точек входа, обёрток или замен фреймворка.

#### Scenario: Сверка перенесённого со складом

- WHEN сравниваются файлы, присутствующие и в складе, и в консоли
- THEN они совпадают побайтово

#### Scenario: Своё в консоли складу не мешает

- WHEN в консоли есть собственный компонент, которого нет в складе
- THEN это не считается расхождением

#### Scenario: В консоли нет неподключённого

- WHEN сравнивается состав разделов консоли и склада
- THEN в консоли отсутствуют разделы склада, не подключённые к платформе

#### Scenario: Внешний вид совпадает с источником

- WHEN оператор открывает любой раздел панели
- THEN экран визуально совпадает с соответствующим экраном исходной вёрстки

#### Scenario: Тексты видимых разделов на русском

- WHEN оператор с локалью по умолчанию открывает любой видимый раздел панели
- THEN заголовки, подписи меню, колонки таблиц, кнопки, пустые состояния, диалоги, тосты и сообщения об ошибках отображаются на русском языке

## ADDED Requirements

### Requirement: Консоль работает только против платформы

Слой данных консоли SHALL обращаться к API платформы без альтернативного режима демонстрационных данных. Ветвление «платформа или демо-данные», демонстрационные хранилища и наборы MUST NOT оставаться в коде: раздел без платформы не собирается вовсе.

#### Scenario: Один источник данных

- WHEN раздел консоли запрашивает данные
- THEN запрос уходит в API платформы, альтернативной ветки выполнения нет

#### Scenario: Платформа недоступна

- WHEN API платформы не отвечает
- THEN раздел показывает ошибку платформы, а не подставляет демонстрационные данные

### Requirement: Правила кода применяются к собственным файлам консоли

Проверка стиля и правил вёрстки SHALL применяться к файлам, написанным для консоли. Файлы, перенесённые из склада без изменений, MUST NOT переформатироваться: их согласованность со складом важнее единообразия стиля внутри консоли. Проверка SHALL быть зелёной.

#### Scenario: Своё проверяется

- WHEN изменяется собственный файл консоли с нарушением правил
- THEN проверка стиля падает

#### Scenario: Перенесённое не трогается

- WHEN запускается форматирование консоли
- THEN файлы, совпадающие со складом, остаются без изменений
