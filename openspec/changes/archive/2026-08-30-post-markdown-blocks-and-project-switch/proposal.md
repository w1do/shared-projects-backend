## Why

Пост в консоли пишется одним куском: блоки формы склеиваются в единую HTML-строку, а обратно читаются одним абзацем — оператор теряет структуру при каждом сохранении, а сайт не может собрать оглавление, потому что у частей текста нет ни заголовков, ни устойчивых идентификаторов. Редактор при этом даёт HTML, хотя контент нужен в markdown. Верхняя панель занята индикатором «сайт онлайн» и кнопкой создания проекта, но не отвечает на главный вопрос оператора — в каком проекте он сейчас и что в нём происходило; переключиться на другой проект из консоли вовсе нельзя. Подключённые к платформе разделы открываются через полноэкранный скелетон, который на быстром API только добавляет мельтешение. Секция «Автор» в форме поста дублирует то, что платформа и так знает: автор — текущий оператор.

## What Changes

**Верхняя панель и проекты**
- Индикатор «сайт онлайн» и кнопка «Новый проект» заменяются одной кнопкой текущего проекта вида «Название (N)», где N — число событий проекта в журнале действий.
- По клику открывается модальное окно: список проектов оператора для переключения, последние 10 событий текущего проекта и создание нового проекта (для того же оператора, что и раньше).
- Переключение проекта в консоли становится штатным действием: выбранный проект становится текущим, разделы перечитываются под него без перезагрузки страницы вручную.

**Содержимое поста**
- Секция «Содержимое» вместо прежних блоков вёрстки: блок — это пара «название» и текст, текст строго markdown.
- Каждый блок получает устойчивый идентификатор, который переживает сохранение и отдаётся публичному API — сайт собирает по ним оглавление и переключение между частями поста.
- **BREAKING (аддитивно):** пост получает поле `blocks`; поле `body` сохраняется и собирается из блоков, поэтому уже подключённые сайты продолжают работать. Существующие посты переносятся в один блок.
- Редактор текста блока — markdown-редактор `markdown-text-editor`; HTML-редактор в форме поста больше не используется.
- Секция «Автор» из формы поста убирается: автором остаётся оператор, создавший пост, — платформа проставляет его сама.

**Генерация поста по теме**
- Схема ответа модели для текста поста требует список блоков; пост, созданный по теме ресёрча, MUST содержать не менее 10 блоков с собственными заголовками и markdown-текстом.
- Пресет схемы «Пост» приводится к тому же составу — каталог пресетов остаётся согласован с тем, что платформа разбирает.

**Загрузка разделов**
- Подключённые к платформе разделы (категории, блог, ресёрч, инструкции, клиенты, дашборд) открываются сразу, без промежуточного скелетона. Демо-разделы вёрстки не затрагиваются.

## Capabilities

### New Capabilities
- `console-project-switch`: переключение между проектами оператора из верхней панели, счётчик событий текущего проекта и его последние события.

### Modified Capabilities
- `console-project-create`: действие создания проекта переезжает в модальное окно проекта — отдельной кнопки в панели больше нет.
- `content-posts`: содержимое поста задаётся блоками «название + markdown», секция автора убрана, сгенерированный пост содержит не менее 10 блоков.
- `content-service`: контракт поста получает блоки с идентификаторами в admin- и публичном API; `body` собирается из блоков.
- `console-research-ui`: состояние загрузки раздела больше не показывается скелетоном.
- `console-instructs-ui`: состояние загрузки раздела больше не показывается скелетоном.
- `admin-console`: подключённые разделы отрисовываются без промежуточного скелетона.

## Impact

- `packages/cms/content`: миграция блоков поста, `Post`, `UpsertPostDTO`/`PostDTO`/`UpsertPostRequest`/`PostResource`, публичное API контента, ревизии постов.
- `packages/cms/instructs`: схема предустановленной инструкции текста поста (`SystemInstructCatalog`) и пресет «Пост» (`SchemaPresetCatalog`).
- `packages/cms/research`: разбор ответа модели при генерации поста по теме.
- `packages/cms/auth`: выдача числа событий проекта для счётчика (журнал действий уже есть).
- `frontends/admin`: `AdminTopbar` и модальное окно проекта, форма поста (секции «Содержимое», удаление «Автор»), слой данных постов и проектов, снятие скелетонов подключённых разделов, реестр текстов `console.*`.
- Зависимости панели: `markdown-text-editor` — новая зависимость, `bun.lock` пересчитывается.
- Тесты: Pest в `apps/content-service`, node-тесты слоя данных консоли, сценарии e2e верхней панели и формы поста.
- `openapi/`: пересборка единой спецификации.
