## MODIFIED Requirements

### Requirement: Посты

Admin API SHALL поддерживать CRUD постов проекта: заголовок, slug, контент, локаль, автор, привязка к категориям, обложка и баннер — ссылки на медиа-файлы того же проекта, статусы `draft → scheduled → published → archived` (недопустимые переходы отклоняются), отложенная публикация по времени. Контент SHALL храниться списком блоков: у каждого блока идентификатор, название и текст в markdown; порядок блоков сохраняется. Идентификатор блока MUST оставаться прежним при последующих сохранениях поста и MUST быть уникален в пределах поста. Обложка и баннер MAY быть пустыми и MUST ссылаться только на медиа текущего проекта; ссылка на медиа другого проекта или на несуществующий файл SHALL отклоняться. Admin и публичное API SHALL отдавать блоки поста и адреса его изображений ссылками платформы. Единый текст поста SHALL оставаться в ответе и собираться из блоков, чтобы уже подключённые сайты продолжали работать. Каждое сохранение SHALL создавать ревизию с возможностью восстановления, включая состав и порядок блоков.

#### Scenario: Отложенная публикация

- WHEN пост в статусе scheduled со временем в будущем
- THEN после наступления времени он публикуется автоматически и появляется в публичном API

#### Scenario: Восстановление из ревизии

- WHEN оператор восстанавливает пост из ревизии
- THEN контент равен снимку, включая состав, порядок и идентификаторы блоков, создаётся новая ревизия

#### Scenario: Блоки в ответе

- WHEN клиент запрашивает пост с несколькими блоками
- THEN ответ содержит блоки в заданном порядке, у каждого — идентификатор, название и текст

#### Scenario: Единый текст собран из блоков

- WHEN клиент читает пост по прежнему контракту, без учёта блоков
- THEN в ответе есть единый текст поста, собранный из его блоков

#### Scenario: Идентификаторы блоков устойчивы

- WHEN пост сохраняется повторно с изменёнными названиями и порядком блоков
- THEN идентификаторы прежних блоков не меняются, а новый блок получает свой идентификатор

#### Scenario: Изображения поста в ответе

- WHEN клиент запрашивает пост с заданной обложкой
- THEN ответ содержит ссылку платформы на изображение обложки

#### Scenario: Чужое медиа

- WHEN пост сохраняется со ссылкой на медиа другого проекта
- THEN запрос отклоняется ошибкой валидации, пост не изменяется

#### Scenario: Существующий пост переносится в блок

- WHEN пост, созданный до появления блоков, читается после перехода
- THEN его прежний текст доступен одним блоком, а единый текст поста не меняется
