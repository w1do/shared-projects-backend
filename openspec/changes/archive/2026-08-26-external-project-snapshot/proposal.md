# Proposal: external-project-snapshot

## Why

Уже работающим проектом, живущим на своём сервере со своим API, из платформы управлять нельзя: консоль показывает только разделы сервисов, которые платформа сама поставила (`content`, `analytics`, `pay`, ядро `auth`), а их экраны захардкожены в вёрстке. Чтобы такой проект попал в единую систему, сегодня пришлось бы переписать его под платформу или рисовать ему экраны руками.

При этом платформа уже описывает консоль декларативно: `ServiceManifest` объявляет `permissions[]` и `navigation[]`, `bootstrap` собирает из этого меню, а видимость разделов считается по «сервис включён + есть право» (`console-navigation`). Не хватает только двух вещей: способа зарегистрировать описание, которое платформа не поставляла, и обобщённого рендерера для разделов, у которых нет экрана в вёрстке.

## What Changes

- **Снапшот внешнего проекта**: оператор загружает JSON-описание (`schema_version`, `project`, `api`, `permissions[]`, `sections[]`), платформа валидирует его и сохраняет как версию, привязанную к проекту. Активная версия участвует в `bootstrap` наравне с манифестами сервисов.
- **Разделы из снапшота в меню**: секции снапшота попадают в консоль тем же путём, что и навигация манифестов, и подчиняются существующему правилу видимости — раздел показывается, только если у оператора есть объявленное для него право.
- **Обобщённый рендерер разделов**: два типа представления в первой версии — `table` (список по декларации: источник строк, колонки, типы, пагинация, поиск) и `external` (переход в чужой интерфейс). Экраны не пишутся под каждый проект: консоль рисует их по описанию штатным `DataGrid` вёрстки.
- **Прокси внешних вызовов**: запросы к API внешнего проекта идут через платформу, а не напрямую из браузера. Хост проверяется по белому списку из снапшота, учётные данные хранятся в настройках проекта и в браузер не попадают.
- **Версионирование и откат**: каждая загрузка — новая версия снапшота; предыдущая сохраняется, откат возвращает прежний состав разделов.
- **Не входит**: действия над строками (POST/DELETE по кнопке), формы создания и редактирования, вложенные разделы, детальные карточки, графики и дашборды, автоматический вывод колонок из ответа без декларации, загрузка снапшота по API самим внешним проектом (в первой версии — только оператором через панель), выполнение произвольного кода из снапшота.

## Capabilities

### New Capabilities

- `external-project-snapshot`: регистрация внешнего проекта декларативным JSON-снапшотом (состав разделов, права, описание источников данных), его версионирование и участие в составе консоли.
- `snapshot-section-rendering`: отрисовка разделов, у которых нет экрана в вёрстке, по декларации снапшота, и обращение к внешнему API через прокси платформы.

### Modified Capabilities

нет. `console-navigation` не архивирован, и его требования не меняются: снапшот отдаёт свои разделы в том же виде, в каком их отдают манифесты сервисов, и существующее правило видимости («сервис включён + есть право») применяется к ним без изменений.

## Impact

- **auth-service / `packages/cms/auth`**: новая таблица версий снапшотов и связь с проектом; загрузка, валидация, активация и откат версии; регистрация прав из снапшота на проект; включение активного снапшота в ответ `bootstrap`. Список переключаемых сервисов (`cms-auth.php`) для внешних проектов не используется — у них отдельный путь регистрации.
- **Прокси внешних вызовов**: новый эндпоинт платформы, который выполняет запрос к API внешнего проекта по описанию из снапшота, с проверкой хоста по белому списку и подстановкой учётных данных из настроек проекта.
- **`frontends/admin`**: маршрут-каталог для разделов снапшота, рендерер `table` и `external`, расширение слоя видимости разделов (`section-access.ts`) ключами из снапшота, экран загрузки и истории версий снапшота в настройках проекта.
- **Документация**: `docs/admin-console.md` — схема снапшота, правила рендера, порядок загрузки и отката.
- **Безопасность**: URL приходят из загруженного пользователем файла — прокси обязан ограничивать хосты и не выпускать запросы во внутреннюю сеть; учётные данные внешнего API не покидают бекенд.
- **Приоритет**: задача не срочная, выполняется после текущей очереди изменений.
