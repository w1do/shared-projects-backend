# snapshot-section-rendering

## Purpose

Определяет, что видит оператор в разделе, у которого нет собственного экрана в вёрстке: панель строит его по декларации снапшота, а данные получает от внешнего API через платформу, не обращаясь к чужому серверу напрямую из браузера.

## ADDED Requirements

### Requirement: Раздел-список строится по декларации

Раздел с представлением типа «список» SHALL отображаться как таблица, состав и порядок колонок которой определяются снапшотом. Каждая колонка MUST иметь подпись и тип отображения; значения SHALL форматироваться согласно типу. Панель MUST NOT показывать поля, не объявленные в снапшоте. Денежные значения SHALL передаваться в минорных единицах и отображаться согласно указанной валюте.

#### Scenario: Таблица по описанию

- **WHEN** оператор открывает раздел снапшота с представлением типа «список»
- **THEN** отображается таблица с объявленными колонками в объявленном порядке, значения отформатированы по типам колонок

#### Scenario: Ответ содержит лишние поля

- **WHEN** внешний API возвращает поля, не объявленные в снапшоте
- **THEN** они не отображаются, а таблица остаётся в объявленном виде

#### Scenario: Поле отсутствует в ответе

- **WHEN** объявленная колонка отсутствует в очередной строке ответа
- **THEN** ячейка отображается пустой, остальная таблица показывается штатно

### Requirement: Постраничный просмотр и поиск по объявленным правилам

Если снапшот объявляет постраничный просмотр, раздел SHALL запрашивать страницы согласно объявленным правилам и показывать элементы управления страницами. Если объявлен поиск, раздел SHALL передавать поисковый запрос внешнему API объявленным способом. Если постраничный просмотр или поиск не объявлены, соответствующие элементы управления MUST NOT отображаться.

#### Scenario: Переход по страницам

- **WHEN** оператор переходит на следующую страницу раздела с объявленным постраничным просмотром
- **THEN** запрашивается следующая страница внешнего API, таблица показывает её содержимое

#### Scenario: Поиск не объявлен

- **WHEN** снапшот не объявляет поиск для раздела
- **THEN** поле поиска в разделе не отображается

### Requirement: Раздел-переход открывает внешний интерфейс

Раздел с представлением типа «переход» SHALL вести на объявленный адрес внешнего интерфейса. Панель MUST NOT выдавать содержимое такого раздела за свой интерфейс: оператору SHALL быть видно, что он переходит во внешнюю систему.

#### Scenario: Переход во внешний интерфейс

- **WHEN** оператор открывает раздел с представлением типа «переход»
- **THEN** открывается объявленный внешний адрес, и переход обозначен как внешний

### Requirement: Обращения к внешнему API идут через платформу

Панель SHALL получать данные внешнего проекта только через платформу. Браузер MUST NOT обращаться к API внешнего проекта напрямую и MUST NOT получать учётные данные этого API. Платформа SHALL подставлять учётные данные из настроек проекта на своей стороне.

#### Scenario: Данные приходят через платформу

- **WHEN** оператор открывает раздел-список внешнего проекта
- **THEN** панель запрашивает данные у платформы, а платформа обращается к внешнему API

#### Scenario: Учётные данные не покидают платформу

- **WHEN** раздел обращается к внешнему API, требующему авторизации
- **THEN** учётные данные подставляются платформой и не попадают в браузер

### Requirement: Адреса внешних вызовов ограничены белым списком

Платформа SHALL выполнять запрос только по адресу, хост которого объявлен в снапшоте как разрешённый. Запрос к адресу вне белого списка, а также к адресам внутренней сети платформы, MUST быть отклонён и MUST NOT выполняться. Отклонение SHALL фиксироваться в журнале действий проекта.

#### Scenario: Хост вне белого списка

- **WHEN** раздел пытается обратиться к адресу, хост которого не объявлен в снапшоте
- **THEN** запрос отклоняется, данные не запрашиваются, событие попадает в журнал

#### Scenario: Попытка обращения во внутреннюю сеть

- **WHEN** снапшот объявляет адрес, ведущий во внутреннюю сеть платформы
- **THEN** такой адрес отклоняется при загрузке снапшота либо при выполнении запроса, и обращение не выполняется

### Requirement: Отказ внешнего API не ломает панель

Недоступность внешнего API, ошибка авторизации, таймаут или ответ неожиданного вида SHALL приводить к понятному сообщению об ошибке внутри раздела. Панель MUST оставаться работоспособной: остальные разделы и навигация SHALL продолжать работать. Платформа SHALL ограничивать время ожидания ответа внешнего API.

#### Scenario: Внешний API недоступен

- **WHEN** внешний API не отвечает или возвращает ошибку
- **THEN** раздел показывает сообщение об ошибке, остальная панель работает штатно

#### Scenario: Ответ не соответствует описанию

- **WHEN** ответ внешнего API не содержит объявленного источника строк
- **THEN** раздел сообщает о несоответствии описанию, а не показывает пустую таблицу как успешный результат
