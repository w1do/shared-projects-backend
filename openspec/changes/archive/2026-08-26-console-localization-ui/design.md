# Design: console-localization-ui

## Context

Бекенд готов (`cms-localization-package`); панель — CI-сверяемая вёрстка, Settings — вкладки (`TABS` + `TabsContent`), формы — react-hook-form + компоненты `ui/`. Локали проекта приходят в `bootstrap.projects[].locales`; `PATCH /projects/{key}/` принимает `locales`. Словарь — `…/content/translations` (+ `?locale=`), автоперевод — `POST …/translate-missing`.

## Goals / Non-Goals

**Goals:** управление языками целиком из панели; только существующие компоненты; e2e-покрытие.
**Non-Goals:** перевод строк вёрстки, переключатель языка панели, переводы постов.

## Decisions

1. **Вкладка Languages** — новая секция Settings по образцу существующих (`LanguagesSection`), новый пункт в `TABS`. Данные — свои hooks (`useProjectLocales`, `useTranslationsQuery`, мутации), не через `StoreSettings`.
2. **Локали** — строка-ввод + бейджи с удалением; сохранение `PATCH` проекта; первая локаль помечена «default». Удаление локали не трогает уже сохранённые значения (бекенд хранит их дальше) — предупреждение в UI.
3. **Словарь** — таблица `Table` вёрстки: ключ, input на локаль, бейдж `machine`, Save/Delete на строку; форма добавления ключа; поиск фильтрует по ключу локально (словари — сотни ключей).
4. **Форма категории** — вместо одного `Input name` в режиме api рендерится input на локаль (`name.{locale}`); схема формы получает `nameTranslations`; сервис шлёт объект. Mock-режим — прежняя строка.
5. **Локали в панели** берутся из `bootstrap` текущего проекта (снимок уже запрашивается при входе; для форм — запрос `getBootstrap()` через TanStack Query с кэшем).

## Risks / Trade-offs

- [Вкладок в Settings станет 7 — теснота на узких экранах] → TabsList уже скроллится горизонтально в вёрстке.
- [Удаление локали может «спрятать» переводы] → предупреждающий текст; данные не удаляются.
- [Правки сверяемой вёрстки] → зеркалирование + diff перед завершением.

## Migration Plan

Аддитивно, только панель. Откат — убрать вкладку и вернуть поле имени.
