# Proposal: console-localization-ui

## Why

Бекенд локализации готов (`cms-localization-package`): словарь, переводимые имена категорий, автоперевод, версия в bootstrap — но в панели этого не видно и управлять языками оператор не может: локали, ключи и переводы доступны только через API.

## What Changes

- **Вкладка Languages в Settings**: управление локалями проекта (список, добавление/удаление; первая — локаль по умолчанию), таблица словаря с поиском, редактированием значений по локалям и удалением ключей, бейдж «machine» у автопереводов, кнопка «Translate missing» (ставит фоновый автоперевод).
- **Форма категории**: имя вводится по локалям проекта (режим api); строковая совместимость mock-режима сохраняется.
- Всё из существующих компонентов вёрстки, зеркалится в `source-admin`, покрывается сценариями Playwright.
- **Не входит**: перевод строк самой админ-вёрстки и переключатель языка панели; экраны переводов постов.

## Capabilities

### New Capabilities

- `console-localization-ui`: управление локалями проекта и словарём переводов из панели, ввод переводимых полей по локалям, запуск автоперевода.

### Modified Capabilities

нет.

## Impact

- `frontends/admin`: слой данных переводов (`platform/localization.ts`, hooks), `LanguagesSection` в Settings, правка формы категории; зеркалирование в `source-admin`.
- `e2e/tests/localization.spec.ts` — сценарии.
- Backend не меняется: используются готовые эндпоинты словаря, `PATCH` проекта и bootstrap.
