# deploy/api-docs Specification (delta)

## Purpose

Единая интерактивная документация API платформы: собранная OpenAPI-спека всех четырёх сервисов доступна через gateway по `/api/docs` одним интерфейсом.

## ADDED Requirements

### Requirement: Единая документация на /api/docs

Gateway SHALL отдавать по пути `/api/docs` интерактивный интерфейс документации (Swagger UI) поверх единой OpenAPI-спеки платформы — объединения контрактов auth, content, analytics и pay в один документ; эндпоинты всех сервисов SHALL отображаться одним списком без переключения между сервисами. Сам документ спеки SHALL быть доступен по `/api/docs/openapi.json`. Документация SHALL подниматься вместе со стеком и SHALL быть доступна как локально, так и по домену развёрнутой площадки.

#### Scenario: Интерфейс объединяет все сервисы

- **WHEN** открывается `/api/docs` на развёрнутом стеке
- **THEN** интерфейс показывает эндпоинты всех четырёх сервисов из единой спеки (включая auth, content, analytics, pay и модуль лицензирования)

#### Scenario: Спека доступна как JSON

- **WHEN** запрашивается `/api/docs/openapi.json`
- **THEN** ответ — валидный OpenAPI-документ объединённого контракта платформы

### Requirement: Актуальность документации

Источником `/api/docs` SHALL быть версионируемый объединённый swagger-файл репозитория, собираемый штатной командой сборки документации; после пересборки файла и redeploy стека документация SHALL отражать добавленные и изменённые эндпоинты без дополнительных настроек.

#### Scenario: Новый эндпоинт появляется в документации

- **WHEN** сервис добавил эндпоинт, объединённый swagger-файл пересобран и стек переразвёрнут
- **THEN** `/api/docs` показывает новый эндпоинт
