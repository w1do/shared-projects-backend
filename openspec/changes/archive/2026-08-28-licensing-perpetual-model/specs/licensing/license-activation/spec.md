# licensing/license-activation Specification (delta)

## Purpose

Клиентский контракт лицензирования для self-hosted-поставок: учёт установок с лимитом, активация ключа, ежесуточный refresh, деактивация при переезде, подписанные Ed25519-токены с entitlements и офлайн-активация для закрытых контуров.

## ADDED Requirements

### Requirement: Учёт установок лицензии

Система SHALL вести реестр установок лицензии: `install_id` (64 hex-символа, генерируется поставкой), `domain`, `app_version`, `last_ip`, `last_seen_at`, отметка отзыва. Пара лицензия+`install_id` SHALL быть уникальна. Активной SHALL считаться установка без отметки отзыва; число активных установок SHALL NOT превышать `max_installations` лицензии — активация новой установки сверх лимита SHALL отклоняться ошибкой `installation_limit_reached` (HTTP 409). При каждой активации и refresh система SHALL обновлять `domain`, `app_version`, `last_ip`, `last_seen_at` установки. Оператор с правом `pay.licensing.manage` SHALL иметь возможность отозвать отдельную установку; отозванная установка SHALL NOT проходить активацию и refresh.

#### Scenario: Лимит установок исчерпан

- **WHEN** по лицензии с `max_installations = 1` и одной активной установкой приходит активация с новым `install_id`
- **THEN** система возвращает HTTP 409 с ошибкой `installation_limit_reached` и русским `message`; новая установка не создаётся

#### Scenario: Повторная активация той же установки не занимает слот

- **WHEN** активация приходит с `install_id` уже существующей активной установки этой лицензии
- **THEN** новая запись не создаётся, телеметрия установки обновляется, выдаётся свежий токен

#### Scenario: Отзыв отдельной установки оператором

- **WHEN** оператор с правом `pay.licensing.manage` отзывает установку, после чего с её `install_id` приходит refresh
- **THEN** установка помечена отозванной, refresh отклоняется, слот лимита освобождён для других установок

### Requirement: Активация и refresh выдают лицензионный токен

Система SHALL предоставлять публичные эндпоинты `POST license/activate` и `POST license/refresh`, принимающие `key`, `install_id`, `domain`, `app_version`. Лицензия SHALL определяться по `sha256`-хэшу нормализованного ключа без передачи идентификатора проекта; неизвестный ключ → HTTP 404 `license_not_found`; refresh с неизвестным `install_id` → HTTP 404 `unknown_installation`; невалидные поля → HTTP 422 `validation_failed`. Успешный ответ SHALL содержать подписанный лицензионный токен, состояние и интервал следующего refresh. Токен SHALL выдаваться всегда, включая отозванную лицензию — с `status: revoked` в payload и HTTP 200; голый отказ без подписанного токена SHALL NOT возвращаться. Перед выдачей система SHALL пересчитать эффективную `entitled_version` по каталогу релизов (см. `licensing/releases`). Ответы об ошибках SHALL содержать машинный код `error` и русский `message`.

#### Scenario: Активация валидным ключом

- **WHEN** поставка отправляет `POST license/activate` с ключом активной лицензии, новым `install_id`, доменом и версией в пределах лимита установок
- **THEN** создаётся установка, ответ HTTP 200 содержит токен, проверяемый публичным ключом проекта, и интервал следующего refresh

#### Scenario: Отозванная лицензия получает revoked-токен

- **WHEN** поставка выполняет refresh по отозванной лицензии с известным `install_id`
- **THEN** ответ HTTP 200 содержит корректно подписанный токен со `status: revoked` в payload

#### Scenario: Неизвестный ключ

- **WHEN** приходит активация с ключом, которого нет в системе
- **THEN** ответ HTTP 404 с ошибкой `license_not_found` и русским `message`

### Requirement: Формат лицензионного токена

Лицензионный токен SHALL иметь вид `base64url(payload_json) . "." . base64url(signature)` (base64url без паддинга), где `signature` — Ed25519 detached-подпись **сырых байт** `payload_json` приватным ключом проекта. Payload SHALL содержать: `v` (версия контракта, сейчас `1`), `license_id`, `install_id`, `domain`, `edition`, `features` (снимок из лицензии), `entitled_version` (эффективная на момент выдачи), `updates_until` (unix time), `status` (`active`/`revoked`), `issued_at`, `expires_at` (unix time, TTL 30 дней). Подпись SHALL успешно проверяться публичным ключом того же проекта; изменение любого байта payload SHALL делать подпись невалидной.

#### Scenario: Токен проверяется публичным ключом

- **WHEN** выданный токен разбирается на payload и подпись, и подпись сырых байт payload проверяется публичным ключом проекта
- **THEN** проверка проходит, payload содержит `v: 1`, entitlements лицензии и `expires_at` через 30 дней от выдачи

#### Scenario: Порча байта ломает подпись

- **WHEN** в payload-части токена изменён хотя бы один байт
- **THEN** проверка подписи публичным ключом завершается неудачей

### Requirement: Деактивация установки

Система SHALL предоставлять публичный эндпоинт `POST license/deactivate`, принимающий `key` и `install_id`: соответствующая активная установка помечается отозванной, слот лимита освобождается, ответ подтверждает деактивацию. Неизвестный `install_id` → HTTP 404 `unknown_installation`.

#### Scenario: Переезд на новый сервер

- **WHEN** поставка деактивирует установку, после чего активируется с новым `install_id`
- **THEN** деактивация подтверждена, активация нового `install_id` проходит в пределах прежнего лимита

### Requirement: Офлайн-активация

Для поставок в закрытых контурах система SHALL поддерживать офлайн-активацию: оператор с правом `pay.licensing.manage` загружает в админку файл-запрос установки (`install_id`, `domain`, `app_version`, дата формирования) для выбранной лицензии; система регистрирует установку по общим правилам лимита и возвращает файл с лицензионным токеном, `expires_at` которого SHALL составлять 1 год от выдачи. Токен SHALL быть подписан тем же ключом проекта и проверяться тем же публичным ключом, что и онлайн-токены.

#### Scenario: Выпуск офлайн-токена

- **WHEN** оператор загружает файл-запрос установки для активной лицензии с незанятым слотом
- **THEN** установка регистрируется, ответ содержит токен с TTL 1 год, проверяемый публичным ключом проекта

#### Scenario: Офлайн-активация сверх лимита отклоняется

- **WHEN** оператор загружает файл-запрос с новым `install_id` при исчерпанном лимите установок
- **THEN** система возвращает доменную ошибку валидации, установка не создаётся, токен не выдаётся

### Requirement: Rate limit публичных эндпоинтов лицензирования

Все публичные эндпоинты лицензирования (`license/activate`, `license/refresh`, `license/deactivate`, `updates/check`) SHALL быть ограничены rate limit'ом от перебора ключей.

#### Scenario: Поток запросов сверх лимита

- **WHEN** с одного источника поступает поток запросов активации сверх лимита
- **THEN** система отвечает ошибкой ограничения частоты в стандартном envelope
