# Design: admin-e2e-playwright

## Context

См. `proposal.md` — Why.

Ограничения, которые формируют решение:

- Панель `frontends/admin` живёт на Bun и собирается в CI командой `bun install --frozen-lockfile`. **Bun на машине разработки отсутствует**, поэтому обновить `frontends/admin/bun.lock` нечем: добавление devDependency в `frontends/admin/package.json` уронило бы CI на несовпадении лока.
- Корень репозитория — npm-workspaces (`packages/frontend/*`) с `package-lock.json`; npm доступен.
- Стек поднимается `./tools/cms up`; всё, включая панель, отдаётся одним gateway на `http://localhost:8080` (`/` → `/admin`).
- Демо-окружение создаётся `tools/smoke.sh`: оператор `root@example.com`, проект `demo`, включённые сервисы `content`, `analytics`, `pay`.
- Панель — production-сборка внутри контейнера (`bun run build && bun run start`), а не dev-сервер: правки видны только после перезапуска контейнера.
- Сессия оператора живёт в cookies `auth_token`, `auth_role`, `project_key`, `console_sections` и в `localStorage` (`current_user`, `console_sections`). Меню рендерится по снимку из localStorage, guard `src/proxy.ts` — по cookie.
- В окружении есть WSLg: `DISPLAY=:0`, сокет `/tmp/.X11-unix/X0`, браузеры Playwright уже закэшированы в `~/.cache/ms-playwright`.

## Goals / Non-Goals

**Goals:**

- Один набор сценариев, который одинаково выполняется человеком (видно на экране) и в CI.
- Проверять то, что видит оператор, а не только коды ответов.
- Прогон не оставляет за собой изменённого состояния проекта.

**Non-Goals:**

- Попиксельное сравнение скриншотов: вёрстка переносится из `source-admin` и меняется, такой тест будет ложно падать.
- Замена юнит-тестов панели: селектор видимости дешевле и точнее проверять юнитом, e2e отвечает за сборку целиком.
- Тестирование внешних сервисов и сторонних API.

## Decisions

### 1. Harness живёт вне пакета панели

`@playwright/test` ставится не в `frontends/admin`, а отдельно; сценарии — в `e2e/`.

Причина прямая: Bun на машине разработки нет, а CI ставит панель с `--frozen-lockfile`. Правка `frontends/admin/package.json` без пересчитанного `bun.lock` — гарантированно красный билд. Альтернатива — поставить bun только чтобы обновить лок — отвергнута: инструмент проверки не должен требовать второго пакетного менеджера ради одной строки в локе.

Побочная выгода: сценарии обращаются к gateway и проверяют связку «панель + gateway + сервисы», то есть принадлежат репозиторию, а не пакету панели. Расположение вне пакета панели это отражает честнее.

**Уточнено при реализации:** зависимость поставлена не в корневой `package.json`, а в самодостаточный пакет `e2e/` со своим `package.json` и `node_modules`. Причина — корневой `node_modules` на 3192 каталога принадлежит `root` (следы установки, выполненной из контейнера), passwordless `sudo` недоступен, и `npm install` в корне падает с `EACCES` на `rename` при перестроении дерева. Отдельный каталог даёт чистую установку от текущего пользователя, не зависит ни от сломанного корневого дерева, ни от `bun.lock` панели. Каталог `e2e` не входит в `workspaces` корня, поэтому конфликта с npm-workspaces нет. Цена — второй `package-lock.json`; она меньше, чем зависимость прогона от прав на чужие каталоги.

### 2. Сценарии ходят через gateway, а не поднимают панель сами

`baseURL` — `http://localhost:8080` (переопределяется `E2E_BASE_URL`). Playwright не запускает `webServer`: стек поднимается `./tools/cms up`, панель внутри контейнера собрана в production-режиме.

Альтернатива — поднимать `next dev` из Playwright — отвергнута: проверялась бы не та сборка, что работает у оператора, и мимо gateway, то есть без реального прохождения `proxy.ts` за прокси.

Следствие, которое надо помнить: **после правок панели контейнер нужно перезапустить**, иначе сценарии гоняют старую сборку. Это фиксируется в документации и в проверке готовности стека.

### 3. Режим — параметр запуска, набор сценариев один

`headed` включается переменной `E2E_HEADED=1` (локально) и не задаётся в CI. Отдельного набора «визуальных» тестов не заводится: расхождение между тем, что смотрит человек, и тем, что гоняет CI — главный способ получить зелёный CI при сломанном интерфейсе.

Замедление в headed-режиме (`slowMo`) включается вместе с ним, чтобы шаги были различимы глазом.

### 4. Вход — переиспользуемая предпосылка, а не шаг каждого сценария

Вход выполняется один раз, состояние хранения сохраняется (`storageState`) и подставляется сценариям. Это и быстрее, и убирает из сценариев шум, не относящийся к проверяемому требованию.

Тонкость этой панели: меню рендерится по `console_sections` из **localStorage**, а guard — по одноимённой **cookie**. Поэтому сохранять только cookies недостаточно, `storageState` должен включать и localStorage. Проверка входа обязана убедиться, что снимок разделов записан, иначе сценарий про состав меню будет проверять поведение «снимок не готов» (показывается всё) и ложно зеленеть.

### 5. Состояние проекта восстанавливается самим сценарием

Сценарии, меняющие состояние (выключение сервиса `content`), выполняют изменение через API платформы и возвращают исходное значение в `finally`, независимо от исхода проверки.

Альтернатива — полагаться на повторный прогон `tools/smoke.sh` после тестов — отвергнута: это делает прогон разрушительным по умолчанию, а сегодняшний инцидент с затёртой базой показал цену такого умолчания.

Отдельно фиксируется: сценарии работают против проекта `demo` в локальном стеке и не предназначены для запуска против окружения с реальными данными. Базовый адрес задаётся явно, значения по умолчанию — только локальные.

### 6. Артефакты прогона — видео и трейс, сохраняются при падении

`trace: on-first-retry`, `video: retain-on-failure`, `screenshot: only-on-failure`, вывод в `e2e/.artifacts/` (в `.gitignore`). Этого достаточно, чтобы разобрать упавший сценарий постфактум, и не захламляет диск при зелёном прогоне.

### 7. Единая команда запуска

`./tools/cms e2e [--headed]` — тот же путь у человека и у CI, как уже сделано для `test` и `api`. Прямой вызов `npx playwright test` остаётся доступным, но документируется команда.

## Risks / Trade-offs

- [Сценарии гоняют старую сборку панели, если контейнер не перезапущен после правок] → проверка готовности перед прогоном и явная запись в документации; команда `./tools/cms e2e` печатает предупреждение о необходимости перезапуска после изменений в `frontends/admin`.
- [headed-режим требует графического окружения] → по умолчанию headless; headed включается переменной. На машине без дисплея прогон проходит тем же набором.
- [Прогон меняет состояние проекта] → восстановление в `finally`; базовый адрес по умолчанию только локальный.
- [Браузеры Playwright весят сотни мегабайт и их надо ставить в CI] → в CI ставится только Chromium (`--with-deps chromium`), локально используется уже закэшированный.
- [e2e медленнее и более хрупки, чем юнит-тесты] → набор держится маленьким и покрывает только то, что нельзя проверить дешевле: состав меню, отказ по прямому адресу, реакцию на смену состава сервисов.

## Migration Plan

Аддитивно: новый каталог `e2e/` со своими зависимостями, новая команда и новая задача CI. Ничего существующего не ломается, сборка панели не затрагивается. Откат — удалить каталог, команду и задачу CI.

## Open Questions

- Нужен ли отдельный проект Playwright для мобильного разрешения (сайдбар в панели имеет мобильную ветку с быстрыми действиями) — решается после первых сценариев, на структуру harness не влияет.
