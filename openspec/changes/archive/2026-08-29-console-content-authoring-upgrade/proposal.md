## Why

Разделы категорий, блогов, ресёрча и инструкций работают, но ежедневная работа в них неудобна: категории нельзя выбрать пачкой и до подтверждения удаления не видно, какое поддерево уйдёт; у поста вообще нет изображений — форма показывает загрузчик, который кладёт data URL в состояние формы, а у модели поста полей под медиа нет, хотя MinIO и медиа-API уже подключены; разделы ресёрча и инструкций собраны из голой разметки мимо дизайн-системы вёрстки; схему ответа инструкции оператор пишет сырым JSON и не знает, какие поля платформа вообще разбирает; супер-админ не может завести новый проект из консоли, хотя `POST /api/admin/v1/projects` уже есть.

## What Changes

**Категории**
- Множественный выбор чекбоксами в древовидном представлении (сейчас чекбоксы доступны только в плоской таблице, а дерево показывается через `TreeTable` без выбора).
- В подтверждении удаления показываются полные пути выбранных узлов вида `/category/subcategory/other`, а не одно имя.
- Кнопка «Удалить все категории проекта» — отдельное опасное действие с усиленным подтверждением, рядом с удалением выбранных.
- Массовое удаление выполняется одним запросом к content-service, а не серией одиночных `DELETE`.
- Раздел приводится к дизайн-схеме `frontends/source-admin`: тулбар, панель, диалоги — из компонентов вёрстки.

**Посты и медиа**
- У поста появляются обложка и баннер — ссылки на медиа-файлы проекта; они отдаются в admin- и публичном API, показываются в списке и карточке поста.
- Форма поста загружает изображение в MinIO через медиа-API проекта вместо data URL в состоянии формы.
- Кнопка «Подобрать изображение AI» на блоке изображений поста: оператор вводит запрос, видит сетку найденных изображений, выбирает нужное, платформа скачивает его в MinIO проекта и привязывает к посту. Автогенерация поста из темы ресёрча обложку не ставит.
- Поиск изображений идёт в ту же SerpApi-совместимую службу, что и ресёрч, отдельной операцией поиска картинок.

**Ресёрч и инструкции в консоли**
- Разделы ресёрча и инструкций пересобираются на компонентах вёрстки (шапка раздела, карточки-секции, таблицы, бейджи, диалоги) и на принятой структуре `sections/`, как в категориях и блогах.
- Схема ответа инструкции заполняется визуально: список полей с типом, обязательностью и описанием; сырой JSON остаётся запасным режимом для сложных схем.
- Оператор берёт готовый пресет полей по сущности платформы (категория, пост, SEO) и правит его, а не собирает схему с нуля.

**Пресеты схем**
- Платформа отдаёт каталог пресетов схем ответа по своим сущностям: поля, типы, обязательность, краткое назначение. Пресеты выводятся из того, что платформа реально разбирает при генерации, — чтобы модель заполняла ровно ожидаемые поля (особенно в SEO, где полей много).

**Создание проекта**
- В топбаре рядом с индикатором «сайт онлайн» появляется кнопка «Новый проект», доступная оператору с правом создания проектов.
- В диалоге вводится только название; ключ проекта платформа выводит сама и обеспечивает его уникальность.
- Созданный проект чистый: создатель получает роль владельца со всеми правами, включаются сервисы по умолчанию, консоль переключается на новый проект.

## Capabilities

### New Capabilities
- `content-image-search`: поиск изображений во внешней поисковой службе и импорт выбранного изображения в медиатеку проекта.
- `instruct-schema-presets`: каталог пресетов схем ответа по сущностям платформы и их применение при заполнении инструкции.
- `console-project-create`: создание нового проекта оператором из консоли и переход в него.

### Modified Capabilities
- `content-categories`: множественный выбор категорий, полные пути в подтверждении удаления, удаление всех категорий проекта.
- `content-posts`: изображения поста (обложка и баннер), загрузка в медиатеку проекта и подбор изображения поиском.
- `console-research-ui`: раздел ресёрча собран по дизайн-схеме консоли.
- `console-instructs-ui`: схема ответа заполняется визуальным редактором полей с пресетами, сырой JSON — запасной режим.
- `content-service`: массовое удаление категорий, поля изображений у поста, импорт медиа по внешней ссылке.
- `auth-service`: проект создаётся по одному названию, ключ выводит платформа.

## Impact

- `packages/cms/content`: модель `Post` и миграция (обложка, баннер), `PostDTO`/`UpsertPostDTO`/`PostResource`, `CategoryController` (массовое удаление и очистка дерева), `MediaController` (импорт по ссылке), публичное API контента.
- `packages/cms/research`: порт `SerpSearchClient` и `SerpApiSearchClient` — операция поиска изображений, `SearchEngine` — движки поиска картинок, конфиг `cms-research`.
- `packages/cms/instructs`: каталог пресетов схем и его HTTP-выдача рядом с `instructs/categories`.
- `packages/cms/auth`: `CreateProjectDTO`/`CreateProjectRequest` — ключ необязателен, вывод ключа из названия.
- `frontends/admin`: разделы `categories`, `blogs`, `research`, `instructs`, `AdminTopbar`, слой данных `lib/admin/data-source/platform/*`, реестр текстов `console.*`.
- `openapi/`: пересборка единой спецификации (`./tools/cms api`).
- Тесты: Pest в `apps/content-service`, `apps/auth-service`; node-тесты слоя данных консоли.
