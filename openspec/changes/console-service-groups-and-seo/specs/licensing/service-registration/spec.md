## MODIFIED Requirements

### Requirement: Сервис licensing в реестре платформы

Платформа MUST NOT включать `licensing` в реестр переключаемых сервисов: отдельного переключателя лицензирования нет, включённость модуля определяется сервисом `pay`. Лицензирование SHALL сохранять собственный манифест сервиса (ключ `licensing`) с навигацией консольных разделов — тарифные планы лицензий, лицензии, организации, релизы, — публикуемый в auth-service вместе с манифестами остальных сервисов; bootstrap консоли SHALL отдавать навигацию лицензирования только при включённом сервисе `pay`. Права модуля SHALL сохранять существующие имена `pay.licensing.view` и `pay.licensing.manage` — переименований и перенастройки ролей MUST NOT требоваться.

#### Scenario: Переключение сервиса штатным API

- **WHEN** администратор запрашивает список переключаемых сервисов проекта
- **THEN** `licensing` в нём отсутствует, а попытка переключить его штатным API отклоняется

#### Scenario: Навигация приходит вместе с оплатой

- **WHEN** сервис `pay` включён для проекта и консоль перечитывает bootstrap
- **THEN** навигация лицензирования отдаётся четырьмя разделами; после выключения `pay` — не отдаётся

#### Scenario: Имена прав не меняются

- **WHEN** оператору назначена роль с правом `pay.licensing.view`, выданным до этого изменения
- **THEN** право продолжает открывать просмотр лицензирования без перенастройки ролей

### Requirement: Публичная валидация вне переключателя

Публичный эндпоинт онлайн-валидации лицензионных ключей SHALL оставаться доступным независимо от состояния переключателя сервиса `pay`: выключение сервиса MUST NOT нарушать проверку уже выданных лицензий в self-hosted-поставках.

#### Scenario: Валидация при выключенном сервисе

- **WHEN** сервис `pay` выключен для проекта, а поставка отправляет активационный ключ активной лицензии этого проекта
- **THEN** ответ валидации обычный: статус `active`, code плана, коды фич, `expires_at`

## ADDED Requirements

### Requirement: Гейт admin-маршрутов по сервису оплаты

Admin-маршруты модуля лицензирования SHALL быть закрыты гейтом сервиса `pay`: для проекта с выключенным сервисом `pay` они SHALL возвращать 404, данные при этом MUST NOT удаляться. Включение `pay` SHALL открывать и платёжные маршруты, и маршруты лицензирования одновременно.

#### Scenario: Выключенный сервис — 404

- **WHEN** оператор обращается к admin-маршруту лицензирования в проекте с выключенным сервисом `pay`
- **THEN** ответ — 404; после включения сервиса данные доступны в прежнем виде

#### Scenario: Включение оплаты открывает лицензирование

- **WHEN** сервис `pay` включён для проекта
- **THEN** admin-маршруты лицензирования и платёжные маршруты отвечают обычным образом

## REMOVED Requirements

### Requirement: Гейт admin-маршрутов по собственному сервису

**Reason**: Лицензирование перестало быть отдельным переключаемым сервисом — его admin-маршруты гейтятся сервисом `pay`.

**Migration**: Требование заменено на «Гейт admin-маршрутов по сервису оплаты». Проектам, где `licensing` был включён, при внедрении включается `pay`, иначе разделы лицензирования пропадут из консоли.

### Requirement: Включённость по умолчанию во всех проектах

**Reason**: Включать нечего — отдельного переключателя `licensing` больше нет, включённость модуля равна включённости сервиса `pay`.

**Migration**: Записи сервиса `licensing` в состоянии проектов не используются; при внедрении проектам с включённым `licensing` включается `pay`. Новый проект получает лицензирование вместе с включением оплаты.
