# ТЗ: лицензирование self-hosted CRM (perpetual-модель)

Модель: клиент покупает **бессрочное право на версию**, которую получил, и **окно обновлений** на срок подписки. Кончилась подписка — CRM продолжает работать на текущей версии, но новые версии недоступны.

Документ состоит из частей:

| Часть | Что описывает | Кому отдавать агенту |
|---|---|---|
| 1 | Модель лицензирования и контракт | Обоим |
| 2 | Сервер лицензий + приватный registry | Репозиторий микросервиса |
| 3 | Клиент (дистрибутив CRM) | Репозиторий CRM |
| 4 | Релизный процесс и CI | Инфраструктура |
| 5 | Приёмка | — |
| 6 | Антипаттерны | Обоим |

# ЧАСТЬ 1. МОДЕЛЬ И КОНТРАКТ

## 1.1. Что продаётся

| Сущность | Смысл |
|---|---|
| `edition` | Редакция: `standard` / `pro` / `enterprise`. Определяет набор фич |
| `entitled_version` | Максимальная версия, на которую у клиента есть право. Фиксируется в момент покупки |
| `updates_until` | Дата окончания окна обновлений. После неё `entitled_version` перестаёт расти |
| `max_installations` | Сколько копий можно развернуть по одной лицензии |

Продление подписки = сдвиг `updates_until` вперёд и подъём `entitled_version` до актуальной.

## 1.2. Пять состояний инсталла

Это ядро модели. Реализовать строго так:

| Состояние | Когда | Поведение приложения |
|---|---|---|
| `licensed` | Валидный токен, `entitled_version >= текущей версии` | Полная работа, бессрочно |
| `updates_expired` | То же, но `updates_until` в прошлом | **Полная работа**, баннер «обновления недоступны», проверка обновлений отключена |
| `trial` | Токена нет, с первого запуска прошло < 30 дней | Полная работа, счётчик дней в интерфейсе |
| `unlicensed` | Токена нет, триал истёк | Блокировка панели, доступен только экран активации |
| `version_not_entitled` | Токен валиден, но `entitled_version < текущей версии` | Отказ запуска с текстом: откатитесь на версию X или продлите подписку |
| `revoked` | Сервер вернул `status: revoked` | Блокировка (возврат средств, кража ключа) |

**Главное правило: истечение подписки НЕ блокирует CRM.** Клиент заплатил за версию — он ей владеет. Блокируются только те состояния, где он использует то, за что не платил: непройденный триал, неоплаченная версия, отозванная лицензия.

## 1.3. Рычаг вместо блокировки

Основная защита не в проверке кода, а в доступе к образам:

- Docker-образы лежат в приватном registry.
- Pull возможен только с креденшелами лицензии.
- Токен-сервис выдаёт доступ только к тем релизам, что вышли до `updates_until`.

Нет подписки — нет физического доступа к новому коду. Патчить нечего.

## 1.4. Формат ключа

```
CRM-XXXX-XXXX-XXXX-XXXX
```

Алфавит `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` (без `0 O 1 I`). Генерация через `random_int()`. В БД только `hash('sha256', strtoupper(trim($key)))` плюс `key_prefix` для поиска в админке.

## 1.5. Формат лицензионного токена

```
base64url(payload_json) . "." . base64url(signature)
```

Ed25519 detached-подпись (`ext-sodium`). Подпись считается по **сырым байтам** payload_json — тем же, что ушли в base64url. Пересобирать JSON перед проверкой запрещено.

**Подпись (сервер):**

```php
$json = json_encode($payload, JSON_UNESCAPED_SLASHES | JSON_UNESCAPED_UNICODE | JSON_THROW_ON_ERROR);
$token = b64($json) . '.' . b64(sodium_crypto_sign_detached($json, $secretKey));
```

**Проверка (клиент):**

```php
[$p, $s] = explode('.', $token);
$json = base64_decode(strtr($p, '-_', '+/'), true);
$sig  = base64_decode(strtr($s, '-_', '+/'), true);

if (! sodium_crypto_sign_verify_detached($sig, $json, $publicKey)) {
    return null;
}
```

base64url без паддинга: `rtrim(strtr(base64_encode($raw), '+/', '-_'), '=')`.

## 1.6. Payload

```json
{
  "v": 1,
  "license_id": 42,
  "install_id": "9f2c…64 hex",
  "domain": "crm.client.ru",
  "edition": "pro",
  "features": ["api", "warehouse", "telephony"],
  "entitled_version": "1.4.7",
  "updates_until": 1798761600,
  "status": "active",
  "issued_at": 1756368000,
  "expires_at": 1758960000
}
```

| Поле | Тип | Примечание |
|---|---|---|
| `v` | int | Версия контракта, сейчас `1`. Неизвестная версия → токен отвергается |
| `entitled_version` | string | SemVer. Максимальная разрешённая версия |
| `updates_until` | int\|null | Unix time конца окна обновлений |
| `status` | string | `active` / `revoked` |
| `expires_at` | int | TTL **токена**, 30 дней. Не имеет отношения к сроку лицензии |

TTL токена 30 дней, а не 48 часов, как в подписочной модели: здесь токен не является рычагом блокировки, он только переносит entitlements. Клиент в закрытом контуре может годами жить на офлайн-токене.

## 1.7. HTTP-контракт

База: `https://license.example.com/api/v1`. Все запросы `POST`, JSON.

### POST /license/activate

```json
{ "key": "CRM-…", "install_id": "9f2c…", "domain": "crm.client.ru", "app_version": "1.4.2" }
```

`200`: `{ "token": "…", "state": "licensed", "refresh_in": 86400 }`

### POST /license/refresh

Те же поля, тот же ответ. Вызывается раз в сутки.

### POST /license/deactivate

`{ "key": "…", "install_id": "…" }` → `{ "deactivated": true }`. Освобождает слот при переезде.

### POST /updates/check

```json
{ "key": "…", "install_id": "…", "app_version": "1.4.2" }
```

`200`:

```json
{
  "latest_entitled": "1.4.7",
  "latest_available": "1.6.0",
  "image": "registry.example.com/crm/app-1.4:1.4.7",
  "changelog_url": "https://…",
  "security_update": true
}
```

`latest_available` показывается всегда — клиент должен видеть, что он отстал, это стимул продлить.

### Ошибки

| Код | `error` | Когда |
|---|---|---|
| 404 | `license_not_found` | Ключа нет |
| 404 | `unknown_installation` | Незнакомый `install_id` на refresh |
| 403 | `license_revoked` | Лицензия отозвана |
| 409 | `installation_limit_reached` | Исчерпан лимит установок |
| 422 | `validation_failed` | Невалидные поля |

Поле `message` — текст на русском для показа клиенту.

# ЧАСТЬ 2. ЗАДАНИЕ A — сервер лицензий и registry

## 2.1. Ключевая пара

```php
$pair = sodium_crypto_sign_keypair();
base64_encode(sodium_crypto_sign_secretkey($pair)); // → env сервиса
base64_encode(sodium_crypto_sign_publickey($pair)); // → в код CRM
```

Команда `php artisan license:keypair`, приватный ключ в `LICENSE_SECRET_KEY`, никогда в git.

## 2.2. Схема БД

**`licenses`**

| Поле | Тип |
|---|---|
| `id` | bigint PK |
| `company_id` | bigint nullable |
| `key_hash` | char(64) unique |
| `key_prefix` | string(16) |
| `edition` | string(32) |
| `features` | json nullable |
| `entitled_version` | string(20) |
| `updates_until` | date nullable |
| `status` | string(16), `active` / `revoked` |
| `max_installations` | smallint, default 1 |
| `note` | text nullable |
| timestamps | |

**`license_installations`**

| Поле | Тип |
|---|---|
| `id` | bigint PK |
| `license_id` | FK cascade |
| `install_id` | char(64) |
| `domain` | string |
| `app_version` | string(20) nullable |
| `last_ip` | string(45) nullable |
| `last_seen_at` | timestamp nullable |
| `revoked_at` | timestamp nullable |
| timestamps | |

Unique `(license_id, install_id)`.

**`releases`** — каталог выпущенных версий, источник правды для доступа к образам.

| Поле | Тип | Примечание |
|---|---|---|
| `id` | bigint PK | |
| `version` | string(20) unique | SemVer, например `1.4.7` |
| `train` | string(10) | Минорная ветка: `1.4` |
| `repository` | string | `crm/app-1.4` |
| `released_at` | timestamp | По этой дате сверяется `updates_until` |
| `is_security` | boolean | Security-патч |
| `min_upgrade_from` | string(20) nullable | Минимальная версия для прямого апгрейда |
| `changelog_url` | string nullable | |

## 2.3. Логика выдачи токена

1. Найти лицензию по `key_hash`, иначе `404`.
2. Найти/создать установку, проверить `max_installations` и `revoked_at`.
3. Обновить `domain`, `app_version`, `last_ip`, `last_seen_at`.
4. Пересчитать `entitled_version`: максимальная версия из `releases`, у которой `released_at <= updates_until`. Если результат ниже сохранённого в лицензии — берётся сохранённый (право на купленное не отбирается никогда).
5. Собрать payload, `expires_at = now + 30 дней`, подписать, вернуть `200`.

Токен выдаётся **всегда**, включая отозванную лицензию — со `status: revoked`. Голый `403` без токена не отдавать.

## 2.4. Правило security-патчей

Патчи внутри уже разрешённого релиз-трейна доступны **всегда**, даже после истечения `updates_until`.

Пример: право до `1.4.7`, вышел `1.4.8` с закрытой уязвимостью → доступен. Вышел `1.5.0` с новыми фичами → недоступен.

Это не благотворительность. Клиент купил приватность и не должен получить от тебя дырявую CRM в своём контуре. Плюс это снимает главный аргумент за взлом.

## 2.5. Токен-сервис для Docker Registry

Registry (`registry:2` или Harbor) настраивается на внешнюю авторизацию:

```yaml
auth:
  token:
    realm: https://license.example.com/v2/token
    service: crm-registry
    issuer: crm-license-server
    rootcertbundle: /certs/token-signing.crt
```

**`GET /v2/token`** — реализовать по спецификации Docker Registry v2 token authentication:

1. Клиент приходит с HTTP Basic: username = `install_id`, password = лицензионный ключ.
2. Параметры: `service`, `scope` вида `repository:crm/app-1.4:pull`.
3. Проверить лицензию, распарсить имя репозитория, найти по нему `train` в `releases`.
4. Разрешить `pull`, если самый ранний релиз этого трейна вышел не позже `updates_until` **или** трейн уже входит в `entitled_version`.
5. Вернуть JWT (RS256, отдельная от Ed25519 пара ключей, TTL 5 минут) с claims `iss`, `sub`, `aud`, `exp`, `nbf`, `iat`, `jti` и `access` со списком разрешённых scope. При отказе — пустой `access`, а не ошибка: так требует протокол.

**Один релиз-трейн = один репозиторий** (`crm/app-1.4`, `crm/app-1.5`). Registry не умеет ACL по тегам, поэтому разграничение делается на уровне репозиториев.

Логировать каждый pull: лицензия, install_id, репозиторий, IP. Всплеск pull с разных IP по одной лицензии — сигнал об утечке ключа.

## 2.6. Приватный Composer-репозиторий (опционально)

Для клиентов без Docker: Satis, авторизация HTTP Basic теми же креденшелами, те же правила по `updates_until`. Реализовать только если такие клиенты реально есть.

## 2.7. Офлайн-активация

Для закрытого контура без интернета:

1. Клиент в CRM жмёт «Офлайн-активация», получает файл-запрос: `install_id`, `domain`, `app_version`, дата.
2. Вендор загружает файл в админку, выпускает токен с `expires_at = now + 1 год`.
3. Клиент загружает выданный файл обратно в CRM.

Реализовать обязательно: часть покупателей приватности сидит без внешнего доступа.

## 2.8. Админка

- Выпуск лицензии: edition, features, `entitled_version`, `updates_until`, `max_installations`. Ключ показывается один раз.
- Продление подписки: сдвиг `updates_until` + подъём `entitled_version` до актуальной.
- Отзыв лицензии и отзыв отдельной копии.
- Офлайн-активация.
- Каталог релизов: CRUD по `releases`.
- Список установок с версиями и `last_seen_at`.
- Отчёт «кто отстал от жизни»: установки на версиях старше N — материал для отдела продаж.

## 2.9. Тесты

- Валидный ключ → токен, проверяемый публичным ключом.
- `entitled_version` не понижается при истёкшей подписке.
- Security-патч внутри разрешённого трейна доступен после `updates_until`.
- Минорный релиз после `updates_until` недоступен.
- Отозванная лицензия → токен со `status: revoked`, код `200`.
- Превышение `max_installations` → `409`.
- Токен-сервис отдаёт JWT с пустым `access` на неразрешённый репозиторий.
- JWT проходит проверку публичным сертификатом registry.
- Изменение байта в payload ломает подпись.

## 2.10. Критерии приёмки

- [ ] Три эндпоинта лицензии + `/updates/check` работают по контракту
- [ ] Ключи хранятся только как sha256, в логи не пишутся
- [ ] Токен-сервис `/v2/token` совместим с Docker Registry v2
- [ ] `docker pull` разрешённого образа проходит, неразрешённого — нет
- [ ] Security-патчи доступны после истечения подписки
- [ ] Офлайн-активация работает
- [ ] Rate limit `throttle:60,1` на всех публичных эндпоинтах
- [ ] Тесты из 2.9 зелёные

# ЧАСТЬ 3. ЗАДАНИЕ B — дистрибутив CRM

Стек: Laravel + Filament + Octane (RoadRunner).

## 3.1. Конфиг `config/license.php`

```php
return [
    'server'      => env('LICENSE_SERVER', 'https://license.example.com'),
    'public_key'  => 'BASE64_PUBLIC_KEY',   // ВШИТ В КОД, не в .env
    'trial_days'  => 30,
    'refresh_every_hours' => 24,
    'state_cache_seconds' => 60,
];
```

Публичный ключ хардкодится в файле. В `.env` его класть нельзя — клиент подменит на свой и начнёт подписывать себе токены.

Версия приложения проставляется на сборке: `APP_VERSION` как build-arg → `config('app.version')`. Не читать из `.env`, иначе её тривиально подделать.

## 3.2. Таблица `license_state`

Одна строка, `id = 1`.

| Поле | Тип | Назначение |
|---|---|---|
| `license_key` | text nullable | Через `Crypt::encryptString()` |
| `install_id` | char(64) nullable | `bin2hex(random_bytes(32))` при первом запуске |
| `token` | text nullable | Последний валидный токен |
| `first_run_at` | timestamp | Старт триала, пишется при первой миграции |
| `checked_at` | timestamp nullable | |
| `clock_guard_at` | timestamp nullable | Монотонная отметка против перевода часов назад |

Состояние в БД, не в кэше: `php artisan cache:clear` не должен ничего сбрасывать.

## 3.3. `LicenseService`

```php
public function state(): string;               // константы из 1.2
public function isOperational(): bool;         // не заблокировано
public function allows(string $feature): bool; // гейт по редакции
public function payload(): ?array;
public function activate(string $key): array;
public function activateOffline(string $token): void;
public function refresh(): bool;
public function checkUpdates(): ?array;
```

**Алгоритм `state()`:**

1. Часы не переведены назад: `now >= clock_guard_at - 300`, иначе `unlicensed`. После проверки поднять `clock_guard_at` до `now`.
2. Токена нет:
   - `now < first_run_at + trial_days` → **`trial`**
   - иначе → **`unlicensed`**
3. Токен есть, но подпись не сходится, либо `v !== 1`, либо `install_id`/`domain` не совпадают → **`unlicensed`**.
4. `status === 'revoked'` → **`revoked`**.
5. `version_compare(config('app.version'), $payload['entitled_version'], '>')` → **`version_not_entitled`**.
6. `updates_until` в прошлом → **`updates_expired`**.
7. Иначе → **`licensed`**.

Результат кэшируется на 60 секунд.

Протухший `expires_at` токена сам по себе **не** меняет состояние: entitlements остаются в силе, приложение просто пытается обновить токен в фоне. Это принципиальное отличие от подписочной модели.

**Нормализация домена** (обе стороны одинаково):

```php
$host = parse_url(config('app.url'), PHP_URL_HOST) ?: config('app.url');
return strtolower(preg_replace('/^www\./', '', trim($host)));
```

**`activate($key)`** — запрос на сервер, **проверка подписи пришедшего токена до сохранения**, запись состояния, сброс кэша.

**`refresh()`** — раз в сутки. Сеть недоступна или подпись не сошлась → `false`, старый токен не трогаем. Никаких исключений наружу.

## 3.4. Middleware `EnsureLicense`

| Состояние | Поведение |
|---|---|
| `licensed` | Пропустить |
| `updates_expired` | Пропустить + флаг баннера в шаблоны |
| `trial` | Пропустить + счётчик оставшихся дней |
| `unlicensed` | Редирект на `license.activate` (JSON → `402`) |
| `revoked` | Редирект на `license.activate` с текстом причины |
| `version_not_entitled` | Страница-заглушка: «Версия X не входит в лицензию. Откатитесь на Y или продлите подписку» |

Роуты `license.*` пропускаются всегда, иначе активироваться будет невозможно.

Вешается на панель Filament: `->middleware([EnsureLicense::class])` в провайдере панели.

## 3.5. Раздел «Лицензия» в панели

- Текущее состояние, редакция, `entitled_version`, дата окончания обновлений.
- Форма ввода ключа + офлайн-активация файлом.
- Кнопка «Проверить обновления» → `/updates/check`.
- Если `latest_available > latest_entitled` — показать, что вышло дальше, и предложить продлить. Клиент должен видеть, что он отстаёт.

## 3.6. Обновление образа

Точка входа контейнера при старте:

1. `php artisan migrate --force`
2. `php artisan config:cache`, `route:cache`, `view:cache`
3. Старт Octane

**Схему передавать только миграциями. Дампы схемы под клиента не делать.** Дамп не даёт пути обновления: переход с 1.0 на 1.2 превращается в ручной diff под каждую пару версий. Миграции решают это по определению.

Правила миграций:
- Внутри мажорной версии только аддитивные изменения. Никаких `drop column` и переименований — клиент может обновляться через несколько версий разом.
- Каждая миграция идемпотентна и переживает повторный запуск.
- Деструктивные изменения — только в мажорном релизе, с отдельной командой и явным предупреждением.

## 3.7. Octane

- Результат `state()` **не хранить** в `static`-свойстве или синглтоне без TTL. Воркер живёт часами — отозванная лицензия проработает до рестарта.
- Кэш только `Cache::remember()` с TTL 60 секунд.
- `LicenseService` — обычный биндинг, не синглтон с состоянием.

## 3.8. Гейты по редакции

Одной проверки в middleware мало: она снимается одной строкой. Минимум 3–5 независимых точек в разных слоях:

```php
public static function canViewAny(): bool
{
    return app(LicenseService::class)->allows('warehouse');
}
```

## 3.9. Водяные знаки

`install_id` (или его короткий хэш) проставляется в артефакты, покидающие систему: метаданные экспортов Excel, PDF-документы, служебные заголовки API. По утёкшей копии видно, чей ключ. Против взлома не помогает, против тиражирования — да.

## 3.10. Команды

- `license:activate {key}`
- `license:refresh` — при недоступности сервера возвращает SUCCESS с warning, не FAILURE
- `license:status` — состояние в консоль, для поддержки

Расписание:

```php
Schedule::command('license:refresh')
    ->daily()
    ->withoutOverlapping()
    ->when(fn () => random_int(1, 4) === 1); // разброс по времени суток
```

## 3.11. Тесты

- Валидный токен, версия в пределах права → `licensed`.
- `updates_until` в прошлом, версия в пределах права → `updates_expired`, приложение работает.
- Версия выше `entitled_version` → `version_not_entitled`.
- Токена нет, 10 дней с первого запуска → `trial`.
- Токена нет, 40 дней → `unlicensed`.
- `status: revoked` → `revoked`.
- Токен, подписанный чужим ключом → `unlicensed`.
- Чужой `install_id` или `domain` в токене → `unlicensed`.
- Часы сдвинуты назад на сутки → `unlicensed`.
- Сервер недоступен, `expires_at` токена в прошлом → состояние **не меняется**.
- `cache:clear` не меняет состояние.

## 3.12. Критерии приёмки

- [ ] Публичный ключ в коде, версия приложения из build-arg
- [ ] Шесть состояний из 1.2 реализованы точно
- [ ] Истечение подписки не блокирует работу
- [ ] Версия выше оплаченной не запускается
- [ ] Триал 30 дней работает и не сбрасывается через `cache:clear`
- [ ] Офлайн-активация работает
- [ ] Схема только миграциями, повторный `migrate` безопасен
- [ ] Никаких `static`-кэшей состояния
- [ ] Тесты из 3.11 зелёные

# ЧАСТЬ 4. РЕЛИЗНЫЙ ПРОЦЕСС

## 4.1. Версионирование

SemVer. Мажор — ломающие изменения и деструктивные миграции. Минор — фичи. Патч — исправления и безопасность.

Релиз-трейн = минорная ветка (`1.4`), внутри неё выходят патчи. Один трейн = один репозиторий в registry.

## 4.2. Один образ на версию

Отдельных сборок под клиента **не делать**. Иначе каждая security-заплатка превращается в N пересборок и N наборов тестов. Фичи и квоты приходят из токена, образ общий.

## 4.3. Пайплайн релиза

1. Тег `v1.4.7` в git.
2. CI собирает образ с `--build-arg APP_VERSION=1.4.7`.
3. Push в `registry.example.com/crm/app-1.4:1.4.7` и `:latest` внутри трейна.
4. CI дёргает API сервера лицензий: создать запись в `releases` (`version`, `train`, `repository`, `released_at`, `is_security`, `changelog_url`).

Шаг 4 обязателен: пока релиза нет в каталоге, доступ к нему не выдаётся никому.

## 4.4. Документация клиенту

В комплекте поставки: `docker-compose.yml`, инструкция по `docker login` с креденшелами лицензии, порядок обновления (бэкап → pull → up → migrate), политика версий и что происходит по окончании подписки.

# ЧАСТЬ 6. АНТИПАТТЕРНЫ

- Блокировать CRM по окончании подписки. Клиент купил версию — она его. Блокировка убьёт репутацию в сегменте, который платит за приватность.
- Отдавать клиенту дамп схемы вместо миграций.
- Собирать отдельный образ под каждого клиента.
- Держать security-патчи за платной стеной. Дырявая CRM в закрытом контуре — твоя проблема, а не только его.
- Класть публичный ключ или `APP_VERSION` в `.env` вместо кода и build-arg.
- Кэшировать состояние лицензии бессрочно или в статике (смертельно под Octane).
- Отдавать `403` без подписанного токена для отозванной лицензии.
- Единственная точка проверки на всё приложение.
- Забыть офлайн-активацию. Именно клиенты в закрытом контуре платят больше всех.
